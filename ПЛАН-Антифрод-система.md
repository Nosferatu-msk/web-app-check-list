# План работ: Антифрод-система верификации фото

> Дата: 17.09.2026 | Статус: Утверждено | Макеты: `mockups/analytics-visits.html`

## Обзор

Серверная система пост-анализа фото для ТМ и админа. Инженер не блокируется. Результаты проверок (pHash, timestamp, GPS, источник) отображаются на странице «Аналитика визитов».

**Документация:**
- Спецификация: раздел 22
- ТЗ: US-ADM-14, US-TM-14
- Тест-кейсы: TC-AF-001 — TC-AF-030 (30 тестов)

## Этап 2. Серверные проверки (backend)

**Задачи:**

### 2.1. pHash — перцептический хэш
- Утилита `server/src/utils/phash.ts`: sharp → resize 32×32 grayscale → DCT → 64-bit hash
- Функция `hammingDistance(hash1, hash2): number`
- Функция `computePhash(imagePath): Promise<string>`

### 2.2. Сервис верификации
- `server/src/services/photoVerification.ts`:
  - `verifyPhoto(photoId)` — главная функция, вызывает все проверки
  - `checkPhash(photo)` — сравнение с последними 30 фото по оборудованию
  - `checkTimestamp(photo, visit)` — окно визита ±30мин/5мин
  - `checkGps(photo, address)` — Haversine, порог 500м
  - `checkSource(photo)` — camera vs gallery
  - Создание записей в `visit_anomalies`

### 2.3. Интеграция в загрузку фото
- В `server/src/routes/photos.ts` — после сохранения фото вызвать `verifyPhoto(photoId)` асинхронно (не блокировать ответ)
- Передать `capturedAt`, `gpsLat`, `gpsLng`, `photoSource` из FormData в БД

### 2.4. Haversine formula
- Утилита `server/src/utils/geo.ts`: `haversineDistance(lat1, lng1, lat2, lng2): number` (в метрах)

**Файлы:**
- `server/src/utils/phash.ts`
- `server/src/utils/geo.ts`
- `server/src/services/photoVerification.ts`
- `server/src/routes/photos.ts` (правки)

**Тесты:** TC-AF-001 — TC-AF-011

## Этап 3. API аналитики (backend)

**Задачи:**

### 3.1. Роуты
- `server/src/routes/analytics.ts`:
  - `GET /api/analytics/visits` — список визитов с отклонениями (пагинация, фильтры, scope по роли)
  - `GET /api/analytics/visits/:id` — детали визита с отклонениями
  - `PATCH /api/analytics/anomalies/:id` — обновить статус отклонения
  - `PATCH /api/analytics/anomalies/batch` — массовое обновление
  - `POST /api/analytics/visits/:id/reshoot` — запрос пересъёмки
  - `POST /api/analytics/visits/:id/confirm` — подтверждение визита

### 3.2. Бизнес-логика запроса пересъёмки
- Удаление фото (файл + БД)
- Обновление статуса задач (нет фото → `not_started`)
- Обновление статуса визита → `in_progress`
- Обновление статуса заявки (через `visit_requests`)
- Запись в `audit_log`

### 3.3. Middleware авторизации
- Доступ: `tm`, `admin`
- ТМ: фильтрация по своим инженерам (`tm_engineers`)
- Админ: все визиты

### 3.4. Shared types
- `shared/types/index.ts`: интерфейсы `VisitAnomaly`, `AnalyticsVisitsResponse`, `VerificationDetails`

**Файлы:**
- `server/src/routes/analytics.ts`

## Риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| pHash ложные срабатывания для задач «до/после» | Средняя | Сравнение только в рамках одного moment (before с before, after с after) |
| GPS недоступен в помещении | Высокая | GPS — опциональный сигнал, не блокирует. Информационное отклонение `photo_no_gps` |
| iOS вырезает метаданные | Высокая | Не полагаемся на EXIF. GPS через `navigator.geolocation`, timestamp через `Date.now()` |
| Сервер 1 CPU / 1.9 ГБ RAM | — | pHash через sharp — микросекунды. Нет тяжёлых операций |
