# Инструкция по деплою обновлений (15.09.2026)

## Внесённые изменения

### 1. Исправлено дублирование производителя в моделях оборудования
**Проблема:** При выборе модели оборудования отображалось "ИТЕЛМАН СВ-15Г (ИТЕЛМАН)" — производитель дублировался.

**Исправлено:** Теперь отображается только "ИТЕЛМАН СВ-15Г" (если fullModelName уже содержит производителя).

**Файлы:**
- `client/src/pages/VisitPage.tsx`
- `client/src/pages/TaskPage.tsx`
- `client/src/pages/admin/AdminObjectEquipment.tsx`

### 2. Добавлена уникальность типов помещений
**Проблема:** В справочнике типов помещений могли быть дубликаты по названию (например, две записи "Комната приёма пищи").

**Исправлено:**
- Добавлена валидация уникальности `name` при создании/редактировании через админ-панель
- Добавлена проверка уникальности `name` при импорте из CSV
- Добавлено UNIQUE-ограничение на `name` в schema.prisma

**Файлы:**
- `server/prisma/schema.prisma`
- `server/src/routes/admin.ts`
- `server/src/routes/import.ts`

### 3. Серийный номер оборудования
**Проблема:** Серийный номер был необязательным для всех видов оборудования.

**Исправлено:**
- Для **приборов учёта** (ХВС, ГВС, электроэнергии, газ) — серийный номер **обязателен** (только ручной ввод)
- Для **остального оборудования** — серийный номер обязателен, но если не указан, **генерируется автоматически** по правилу:
  ```
  Код объекта / Код типа оборудования / Порядковый номер
  ```
  Пример: `OBJ-001/splitvn/1`, `OBJ-001/splitvn/2`

**Файлы:**
- `server/src/utils/serialNumber.ts` (новая утилита)
- `server/src/routes/admin.ts`
- `server/src/routes/import.ts`
- `server/src/routes/proposals.ts`
- `client/src/pages/VisitPage.tsx`

## Порядок деплоя на production

### Шаг 1. Проверить и удалить дубликаты типов помещений

Подключиться к production-базе данных и выполнить SQL-скрипт:

```bash
# Подключиться к БД
docker compose -f docker-compose.prod.yml exec -T db psql -U checklist -d checklist < server/scripts/fix-room-types-duplicates.sql
```

**Или вручную через psql:**

```sql
-- 1. Проверить наличие дубликатов
SELECT name, COUNT(*) as count
FROM room_types
GROUP BY name
HAVING COUNT(*) > 1;

-- 2. Если есть дубликаты "Комната приёма пищи", удалить их
UPDATE tasks
SET room_type_id = (SELECT MIN(id) FROM room_types WHERE name = 'Комната приёма пищи')
WHERE room_type_id IN (
  SELECT id FROM room_types
  WHERE name = 'Комната приёма пищи'
    AND id != (SELECT MIN(id) FROM room_types WHERE name = 'Комната приёма пищи')
);

DELETE FROM room_types
WHERE name = 'Комната приёма пищи'
  AND id != (SELECT MIN(id) FROM room_types WHERE name = 'Комната приёма пищи');

-- 3. Добавить UNIQUE-ограничение
ALTER TABLE room_types ADD CONSTRAINT room_types_name_key UNIQUE (name);
```

### Шаг 2. Сгенерировать serialNumber для существующего оборудования

```bash
# Скопировать скрипт на сервер
docker cp server/scripts/generate-serial-numbers.ts server:/app/scripts/

# Выполнить генерацию
docker compose -f docker-compose.prod.yml exec -T server npx tsx scripts/generate-serial-numbers.ts
```

Скрипт:
- Найдёт всё оборудование без serialNumber (кроме счётчиков)
- Сгенерирует serialNumber по правилу: `objectCode/equipmentTypeCode/порядковый номер`
- Обновит записи в БД

## Проверка после деплоя

### 1. Проверить уникальность типов помещений
- Зайти в админ-панель → Справочники → Типы помещений
- Попробовать создать тип с существующим названием — должна появиться ошибка
- Проверить, что "Комната приёма пищи" теперь только одна

### 2. Проверить отображение моделей
- Создать визит → Добавить оборудование → Выбрать производителя (например, ИТЕЛМАН)
- В списке моделей должно отображаться "ИТЕЛМАН СВ-15Г", а не "ИТЕЛМАН СВ-15Г (ИТЕЛМАН)"

### 3. Проверить серийные номера
- Добавить прибор учёта (ХВС/ГВС/э/э) без serialNumber — должна появиться ошибка
- Добавить обычное оборудование (например, кондиционер) без serialNumber — serialNumber должен сгенерироваться автоматически
- Проверить в БД, что у старого оборудования появились serialNumber
