# Видимость визитов команды для инженеров

**Дата:** 07.10.2026  
**Статус:** Реализовано  
**Заказчик:** Анна

## Проблема

Два инженера работают на одном объекте и чтобы не дублировать задачи им нужно видеть визиты друг друга и редактировать их. Раньше каждый инженер видел только свои визиты.

## Решение

Реализован **Подход А** — автоматическая видимость визитов команды для инженеров с механизмом блокировки одновременного редактирования.

## Как это работает

### Видимость визитов

1. **Инженер видит:**
   - ✅ Свои визиты (созданные им)
   - ✅ Визиты, где он назначен через `visitEngineers`
   - ✅ Визиты других инженеров из своей команды ТМ

2. **Команда ТМ определяется через:**
   - `TmEngineer` → `tmId` → все инженеры этого ТМ
   - `TmTeamMember` → если ТМ лидер, то инженеры всех ТМ2 команды
   - `TmTeamMember` → если ТМ член команды, то инженеры лидера

### Блокировка одновременного редактирования

1. **Когда инженер открывает визит:**
   - Устанавливается флаг `editingEngineerId` = ID инженера
   - Устанавливается `editingStartedAt` = текущее время

2. **Когда другой инженер пытается открыть тот же визит:**
   - Проверяется `editingEngineerId`
   - Если визит редактируется другим инженером менее 30 минут — показывается предупреждение
   - Если сессия устарела (более 30 минут) — блокировка снимается

3. **Когда инженер закрывает визит:**
   - Блокировка автоматически снимается через 30 минут
   - Или явно вызывается `releaseVisitEditLock()`

### Ограничения

1. **Удаление визита:**
   - ✅ Инженер может удалить только свой визит
   - ❌ Попытка удалить чужой визит показывает ошибку

2. **Редактирование визита:**
   - ✅ Инженер может редактировать визиты коллег по команде
   - ❌ Нельзя редактировать визит, если он заблокирован другим инженером
   - ❌ Нельзя редактировать завершённые или отправленные визиты

## Тестирование

### Сценарии для проверки:

1. **Видимость визитов:**
   - Инженер А создаёт визит → Инженер Б (из той же команды) видит его в списке
   - В списке визитов отображается пометка "Визит коллеги"
   - При открытии визита показывается предупреждение "Вы редактируете визит инженера..."

2. **Блокировка редактирования:**
   - Инженер А открывает визит → начинает редактирование
   - Инженер Б пытается открыть тот же визит → видит предупреждение "Визит в настоящее время редактируется инженером..."
   - Через 30 минут блокировка автоматически снимается

3. **Удаление визита:**
   - Инженер А создаёт визит
   - Инженер Б пытается удалить этот визит → видит ошибку "Вы можете удалять только свои визиты"

4. **Завершённые визиты:**
   - Визит в статусе "completed" или "sent" нельзя редактировать
   - При попытке открытия показывается предупреждение "Визит завершён или отправлен и не может быть изменён"

## Технические детали

### Поля в таблице `visits`:

```sql
editing_engineer_id TEXT       -- ID инженера, который сейчас редактирует визит
editing_started_at  TIMESTAMP  -- Время начала сессии редактирования
```

### Логика блокировки:

```typescript
// Проверка актуальности блокировки (30 минут)
const thirtyMinutesAgo = new Date(Date.now() - 30 * 60 * 1000);
if (visit.editingStartedAt > thirtyMinutesAgo) {
  // Блокировка активна
  return { canEdit: false, editor: ... };
}
// Блокировка устарела — можно редактировать
```

### API endpoints:

- `GET /api/visits` — список визитов (с учётом видимости команды)
- `GET /api/visits/:id` — детали визита (с информацией о блокировке)
- `PUT /api/visits/:id` — обновление визита (с проверкой блокировки)
- `DELETE /api/visits/:id` — удаление визита (только свой визит)
