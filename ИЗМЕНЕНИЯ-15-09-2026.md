### 3. ✅ Серийный номер оборудования
**Проблема:** Серийный номер был необязательным для всех.

**Решение:**

#### Для приборов учёта (ХВС, ГВС, э/э, газ):
- Серийный номер **обязателен**
- Только ручной ввод
- Валидация на клиенте и сервере

#### Для остального оборудования:
- Серийный номер **обязателен**
- Если не указан инженером → **генерируется автоматически**
- Формат: `Код объекта/Код типа оборудования/Порядковый номер`
- Пример: `OBJ-001/splitvn/1`, `OBJ-001/splitvn/2`

**Изменённые файлы:**
- `server/src/utils/serialNumber.ts` (новая утилита генерации)
- `server/src/routes/admin.ts` (валидация + автогенерация)
- `server/src/routes/import.ts` (валидация + автогенерация при импорте)
- `server/src/routes/proposals.ts` (валидация + автогенерация при одобрении)
- `client/src/pages/VisitPage.tsx` (валидация на клиенте + обновлён placeholder)

**Для существующего оборудования:**
- Создан скрипт: `server/scripts/generate-serial-numbers.ts`
- Нужно выполнить на production для генерации serialNumber у существующего оборудования

## Технические детали

### Формат автогенерации serialNumber
```
{objectCode}/{equipmentTypeCode}/{seqNumber}
```

**Примеры:**
- `OBJ-001/splitvn/1` — первый кондиционер на объекте OBJ-001
- `OBJ-001/splitvn/2` — второй кондиционер на объекте OBJ-001
- `OBJ-002/vent/1` — первая вентиляция на объекте OBJ-002

### Счётчики (только ручной ввод)
- `schetchik_electroshc` — Прибор учёта э/э
- `schetchik_hvs` — Прибор учёта ХВС
- `schetchik_gws` — Прибор учёта ГВС
- `meter_gas` — Прибор учёта газопотребления

### Уникальность в БД
`ObjectEquipment` имеет уникальные ограничения:
- `[addressId, equipmentTypeCode, serialNumber]` — нельзя два оборудования одного типа с одинаковым SN на одном объекте
- `[addressId, equipmentTypeCode, locationDescription]` — нельзя два оборудования одного типа с одинаковым расположением
