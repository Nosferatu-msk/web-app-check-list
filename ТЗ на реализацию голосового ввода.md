# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## на реализацию функции голосового ввода (Speech-to-Text) в поле «Дополнительные рекомендации»

**Версия:** 1.1  
**Дата:** 23.07.2026  
**Статус:** Утверждено

---

## 1. ОБЩИЕ СВЕДЕНИЯ

### 1.1. Назначение
Настоящее ТЗ описывает требования к добавлению функции голосового ввода текста в свободное текстовое поле **«Дополнительные рекомендации»** на страницах контролируемых параметров.

### 1.2. Цель
Сократить время заполнения отчета в полевых условиях, особенно когда руки инженера заняты инструментом, загрязнены или он работает в перчатках. Голосовой ввод позволит быстро надиктовать развернутый текст рекомендации без использования экранной клавиатуры.

### 1.3. Область применения
Функция применяется **только** к текстовому полю «Дополнительные рекомендации» (свободный ввод). К чек-боксам «Типовые рекомендации» из справочника голосовой ввод не применяется.

Функция реализуется на **двух страницах**:
- **TaskPage** (`client/src/pages/TaskPage.tsx`) — страница индивидуальной задачи.
- **GroupTaskPage** (`client/src/pages/GroupTaskPage.tsx`) — страница групповой задачи (климатическое оборудование).

## 2. ПОЛЬЗОВАТЕЛЬСКИЙ ИНТЕРФЕЙС И UX

### 2.1. Расположение элемента управления
Пиктограмма микрофона размещается **справа внутри** текстового поля (textarea) «Дополнительные рекомендации». Реализуется через обёртку `VoiceInput` — компонент, объединяющий `TextArea` из Ant Design и кнопку микрофона.

### 2.2. Состояния пиктограммы микрофона

| Состояние | Визуальное отображение | Поведение системы |
| :--- | :--- | :--- |
| **Ожидание (Idle)** | Серый контурный микрофон (например, `#94A3B8`) | Клик запускает процесс распознавания. |
| **Запрос разрешения** | Пульсирующий серый микрофон | Система запрашивает у браузера доступ к микрофону. |
| **Запись (Listening)** | Красный микрофон с пульсирующей анимацией (красные волны) | Идёт распознавание речи. Повторный клик — ручная остановка записи. |
| **Ошибка (Error)** | Красный перечёркнутый микрофон | Ошибка распознавания, нет сети, нет прав. Показывает тултип с причиной. |
| **Недоступно (Disabled)** | Полупрозрачный серый микрофон | Инженер находится в офлайн-режиме. Клик неактивен. |

*Примечание:* Состояние «Обработка (Processing)» исключено — Web Speech API возвращает результат мгновенно, промежуточное состояние не нужно.

### 2.3. Логика вставки текста
* Текст вставляется **в позицию курсора** или **в конец** существующего текста (если курсор не установлен).
* Если в поле уже есть текст, новый надиктованный текст добавляется через пробел.
* Система автоматически удаляет лишние пробелы в начале и конце вставляемого фрагмента (`.trim()`).

### 2.4. Ручная остановка записи
Повторное нажатие на пульсирующий микрофон (состояние «Запись») **останавливает распознавание**. Это необходимо для шумных помещений, где автоостановка по таймауту тишины может не сработать.

### 2.5. Взаимодействие с interim-результатами
Промежуточные результаты (`interim results`) отображаются **курсивом** в конце текста поля, визуально отделяясь от финального текста. После получения финального результата (`final result`) курсивный текст заменяется на обычный. Это предотвращает путаницу у пользователя.

### 2.6. Взаимодействие с автосохранением
- На время записи (состояние «Listening») автосохранение **приостанавливается**.
- После остановки записи (ручной или по таймауту) автосохранение **возобновляется** и сохраняет итоговый текст.
- Это предотвращает множественные срабатывания автосохранения при каждом interim-результате.

## 3. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

### 3.1. Используемый API
Для реализации используется нативный браузерный **Web Speech API** (`SpeechRecognition` / `webkitSpeechRecognition`). Использование сторонних платных API (Google Cloud Speech, Yandex SpeechKit) не требуется, что удешевляет эксплуатацию.

### 3.2. Параметры распознавания
* **Язык:** `lang = 'ru-RU'` (русский язык).
* **Промежуточные результаты:** `interimResults = true` (текст появляется на экране по мере произнесения для обратной связи).
* **Непрерывный режим:** `continuous = true` (распознавание не останавливается автоматически после паузы — инженер может делать паузы для обдумывания формулировки).
* **Ручная остановка:** повторный клик по микрофону вызывает `recognition.stop()`.
* **Таймаут тишины (fallback):** автоматическая остановка записи через **5 секунд** тишины — на случай, если инженер забыл остановить запись вручную.

### 3.3. Совместимость браузеров
* **Android (Chrome, Edge):** Полная поддержка Web Speech API.
* **Android (Samsung Internet):** Частичная поддержка — `continuous = true` и `interimResults` могут работать нестабильно. Рекомендуется тестирование.
* **iOS (Safari 14.5+):** Поддержка `webkitSpeechRecognition`. *Примечание: на iOS Safari при первом нажатии может потребоваться явное разрешение доступа к микрофону на уровне ОС.*

### 3.4. TypeScript-типы
Стандартные `@types/typescript` не содержат определений для `SpeechRecognition`. Необходимо:
- Установить пакет `@types/dom-speech-recognition` (devDependency), **или**
- Добавить ambient declaration в `client/src/types/speech-recognition.d.ts`.

## 4. АРХИТЕКТУРА РЕАЛИЗАЦИИ

### 4.1. Кастомный хук `useSpeechRecognition`

Создаётся переиспользуемый хук `client/src/hooks/useSpeechRecognition.ts`, инкапсулирующий всю логику работы с Web Speech API.

**Интерфейс хука:**

```typescript
interface UseSpeechRecognitionReturn {
  isListening: boolean;       // идёт ли запись
  isSupported: boolean;       // поддерживается ли Speech API в браузере
  interimTranscript: string;  // промежуточный текст (interim results)
  startListening: () => void; // начать распознавание
  stopListening: () => void;  // остановить распознавание
  error: string | null;       // текст ошибки (если возникла)
}
```

**Логика хука:**
- При `startListening()`: создаёт экземпляр `SpeechRecognition`, настраивает параметры, запускает.
- При `onresult`: разделяет результаты на `final` и `interim`, обновляет состояние.
- При `onerror`: устанавливает текст ошибки.
- При `onend`: если запись не была остановлена вручную и сработал таймаут — останавливает.
- При `stopListening()`: вызывает `recognition.stop()`.

### 4.2. UI-компонент `VoiceInput`

Создаётся компонент `client/src/components/VoiceInput.tsx`, объединяющий:
- `TextArea` из Ant Design (с `ref` для управления позицией курсора).
- Кнопку микрофона (иконка `AudioOutlined` из `@ant-design/icons`), позиционированную абсолютно внутри поля.
- Логику вставки текста с учётом позиции курсора (`selectionStart` / `selectionEnd`).
- Индикацию состояний (цвет, анимация, тултип).
- Использование хука `useOnlineStatus` (существующий хук в проекте) для определения офлайн-режима.

### 4.3. Позиция курсора в Ant Design TextArea

Ant Design `TextArea` — обёртка над `<textarea>`. Для получения позиции курсора:
1. Перед записью сохраняется `selectionStart` через `ref.current.resizableTextArea.textArea.selectionStart`.
2. После получения финального текста — текст вставляется в сохранённую позицию через `form.setFieldsValue()`.
3. Если `selectionStart` не определён (курсор не установлен) — текст добавляется в конец.

### 4.4. Интеграция в страницы

Компонент `VoiceInput` заменяет стандартный `TextArea` в поле «Дополнительные рекомендации»:
- **TaskPage.tsx** (строка ~613): `<TextArea rows={3} .../>` → `<VoiceInput rows={3} .../>`
- **GroupTaskPage.tsx** (строка ~297): аналогичная замена.

## 5. РАБОТА В ОФЛАЙН-РЕЖИМЕ (КРИТИЧНО)

Поскольку приложение является PWA и часто используется в подвалах/серверных без интернета, необходимо учитывать, что **Web Speech API требует активного подключения к сети** (распознавание происходит на серверах Google/Apple).

**Логика поведения в офлайне:**
1. Используется существующий в проекте хук `useOnlineStatus` (файл `client/src/hooks/useOnlineStatus.ts`).
2. При переходе приложения в режим офлайн (отсутствие сети) пиктограмма микрофона переходит в состояние **«Недоступно (Disabled)»**.
3. При наведении/тапе на неактивный микрофон отображается всплывающая подсказка (тултип): 
   > *«Голосовой ввод недоступен без подключения к интернету. Используйте текстовый ввод.»*
4. При восстановлении сети пиктограмма автоматически возвращается в активное состояние.

## 6. ОБРАБОТКА ОШИБОК И ПОГРАНИЧНЫХ СЛУЧАЕВ

| Ситуация | Действие системы |
| :--- | :--- |
| **Пользователь запретил доступ к микрофону** | Показать модальное окно: *«Доступ к микрофону запрещён. Пожалуйста, разрешите доступ в настройках браузера для использования голосового ввода.»* |
| **Распознавание не удалось (шум, невнятная речь)** | Показать тултип у поля: *«Не удалось распознать речь. Попробуйте ещё раз или введите текст вручную.»* Текст в поле не изменяется. |
| **Сеть пропала во время диктовки** | Запись автоматически прерывается. Распознанный до обрыва сети текст (final results) сохраняется в поле. Появляется уведомление: *«Связь потеряна. Голосовой ввод остановлен.»* |
| **Пользователь нажал микрофон, но молчит** | Запись автоматически останавливается через 5 секунд тишины. Текст не добавляется. |
| **Пользователь не остановил запись вручную** | Fallback: автоматическая остановка через 5 секунд тишины. |
| **Speech API не поддерживается браузером** | Пиктограмма микрофона не отображается (компонент `VoiceInput` рендерит обычный `TextArea` без кнопки). |

## 7. БЕЗОПАСНОСТЬ И ПРИВАТНОСТЬ

1. Данные с микрофона **не отправляются** напрямую на бэкенд приложения. Они обрабатываются браузером и сервисами ОС (Google/Apple), в приложение возвращается только итоговый текст.
2. При **первом использовании** голосового ввода отображается информационное сообщение:
   > *«Голосовой ввод использует сервисы распознавания речи вашего браузера (Google/Apple). Не диктуйте конфиденциальную информацию и персональные данные.»*
   
   Сообщение показывается один раз (флаг сохраняется в `localStorage`).
3. Это соответствует общему подходу приложения к 152-ФЗ (аналогично предупреждению при фотофиксации).

## 11. ТЕХНИЧЕСКИЕ ЗАМЕТКИ ДЛЯ РАЗРАБОТЧИКОВ

1. **iOS Safari Quirks:** В iOS Safari `SpeechRecognition` может работать нестабильно, если страница не была взаимодействовала с пользователем (требует `user gesture`). Убедитесь, что запуск распознавания жестко привязан к событию `click` или `touchstart`.
2. **Текстовые артефакты:** Движки распознавания часто добавляют пробелы в начале и конце фразы. Обязательно используйте `.trim()` перед вставкой в поле.
3. **Пунктуация:** Стандартный Web Speech API в русском языке часто не распознаёт слова «точка» или «запятая» как знаки препинания. *Решение:* не усложнять ТЗ обработкой пунктуации на клиенте. Инженер сможет быстро расставить знаки препинания вручную после диктовки.
4. **Безопасность:** Данные с микрофона **не отправляются** напрямую на бэкенд приложения. Они обрабатываются браузером и сервисами ОС (Google/Apple), в приложение возвращается только итоговый текст.
5. **Samsung Internet:** Поддержка `continuous = true` и `interimResults` может быть ограничена. При обнаружении проблем — fallback на `continuous = false` с детекцией браузера.
6. **Существующие хуки:** использовать `useOnlineStatus` из `client/src/hooks/useOnlineStatus.ts` для определения офлайн-режима (не создавать новый механизм).
