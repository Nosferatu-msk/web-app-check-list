## 1. ОБЩИЕ СВЕДЕНИЯ

### 1.1. Назначение
Настоящее ТЗ описывает требования к адаптации интерфейсов ролей **Инженер**, **Территориальный менеджер (ТМ)** и **Администратор** под различные устройства: смартфоны (iPhone 11-17, Xiaomi, Redmi Note, Oppo, Samsung и др.), планшеты (iPad, Android-планшеты) и ПК.

### 1.2. Ключевые цели
- **Полное отсутствие горизонтальной прокрутки** на любых экранах (от 320px до 1920px+).
- Оптимизация пространства: замена громоздких текстовых элементов на пиктограммы и компактные UI-паттерны.
- Обеспечение удобства работы одной рукой (для смартфона) и обеими руками (для планшета).
- Учет технических особенностей мобильных ОС (Safe Area на iPhone, нижняя панель навигации Android, клавиатуры).
- **Сохранение работоспособности PWA в офлайн-режиме** после внедрения адаптивных стилей.

### 1.3. Технологический контекст

Приложение построено на следующем стеке, который необходимо учитывать при реализации:

| Компонент | Технология | Примечание |
|---|---|---|
| UI-библиотека (десктоп) | **Ant Design 5** (`antd@^5.21.0`) | Основная библиотека компонентов |
| UI-библиотека (мобильные) | **antd-mobile** (`antd-mobile@^5.37.0`) | Подключена, но не используется — внедрить для мобильных компонентов |
| Иконки | `@ant-design/icons@^5.5.0` | |
| Темизация | `ConfigProvider` + токены | Настроен только `colorPrimary` |
| PWA | Workbox (Service Worker) + Dexie (IndexedDB) | Офлайн-кэширование |
| Манифест | `manifest.json` (vite-plugin-pwa) | |

**Ключевое архитектурное решение:** для мобильных специфичных компонентов (Picker, SwipeAction, Bottom Sheet) используется `antd-mobile`, для десктопных — `antd`. Выбор определяется через `Grid.useBreakpoint()` или media queries.

## 2. СИСТЕМА АДАПТИВНОСТИ (BREAKPOINTS)

### 2.1. Breakpoints

Приложение использует «резиновую» (fluid) верстку. Breakpoints **привязаны к Ant Design Grid** для согласованности с компонентами библиотеки:

| Тип устройства | Ant Design token | Ширина экрана | Основной интерфейс | Навигация |
| :--- | :--- | :--- | :--- | :--- |
| **Смартфон (Mobile)** | `xs` / `sm` | < 768 px | Карточный вид, одноколоночная верстка | Нижняя панель (Bottom Navigation) |
| **Планшет (Tablet)** | `md` | 768 px – 991 px | Гибридный вид (таблицы/карточки), двухколоночная верстка | Боковая панель (Sidebar) |
| **ПК (Desktop)** | `lg` / `xl` | ≥ 992 px | Таблицы, многоколоночные дашборды | Боковая панель (Sidebar) |

> **Примечание:** Ant Design breakpoints: `xs` <576px, `sm` ≥576px, `md` ≥768px, `lg` ≥992px, `xl` ≥1200px, `xxl` ≥1600px. В CSS используются те же значения для консистентности.

### 2.2. Способ определения устройства

```typescript
// Использование Ant Design Grid
const { md } = Grid.useBreakpoint();
const isMobile = !md; // < 768px

// Для CSS — media queries
@media (max-width: 767.98px) { /* mobile */ }
@media (min-width: 768px) and (max-width: 991.98px) { /* tablet */ }
@media (min-width: 992px) { /* desktop */ }
```

## 3. PWA-АДАПТАЦИЯ

> *Добавлено по результатам ревью: приложение является PWA, необходимо учесть специфику Service Worker, манифеста и viewport.*

### 3.1. Viewport meta tag

Обновить `<meta name="viewport">` в `index.html` для поддержки Safe Area:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover, maximum-scale=1.0, user-scalable=no">
```

- `viewport-fit=cover` — обязательный атрибут для корректной работы `env(safe-area-inset-*)` на iPhone.
- `user-scalable=no` — предотвращает случайное масштабирование при двойном тапе (допустимо для PWA).

### 3.2. Манифест PWA (`manifest.json`)

Обновить через `vite-plugin-pwa` конфигурацию:

```json
{
  "display": "standalone",
  "orientation": "portrait",
  "theme_color": "#1677ff",
  "background_color": "#f5f5f5"
}
```

### 3.3. Service Worker и кэширование стилей

- CSS-файлы кэшируются через Workbox `precaching`. При обновлении стилей необходимо инкрементировать версию кэша (автоматически через `vite-plugin-pwa` при `build`).
- После деплоя новой версии адаптивных стилей — пользователь должен получить обновление при следующем запуске приложения. Проверить через `skipWaiting` + `clientsClaim`.

### 3.4. Safe Area CSS

Обязательные отступы для всех фиксированных элементов (Header, Bottom Navigation):

```css
.app-header {
  padding-top: env(safe-area-inset-top, 0px);
}
.bottom-nav {
  padding-bottom: env(safe-area-inset-bottom, 0px);
}
```

## 4. ОПТИМИЗАЦИЯ ИНТЕРФЕЙСА ИНЖЕНЕРА (MOBILE FIRST)

### 4.1. Страница 1: «Визит» (Чек-лист задач) — VisitPage

**Проблема:** Таблица с колонками «Чекбокс | Вид оборудования | Местоположение | Вложения | Статус» не помещается на экран смартфона. Таблица содержит вложенность: комнаты → оборудование внутри комнаты.

**Решение:** На мобильных устройствах таблица трансформируется в **список карточек (Card List)** с группировкой по комнатам.

**Макет карточки на смартфоне:**

```text
┌─────────────────────────────────────────────┐
│ 📍 Серверная                                │
│ ┌─────────────────────────────────────────┐ │
│ │ Внутр. блок СС          📷 2/2   ✅  ⋮ │ │
│ │ Серверная · Daikin FTXS35K              │ │
│ └─────────────────────────────────────────┘ │
│ ┌─────────────────────────────────────────┐ │
│ │ ⚡ РЩ/ГРЩ               📷 1/1   🔄  ⋮ │ │
│ │ Электрощитовая · ABB GS420              │ │
│ └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

**Структура карточки:**
- **Группировка по комнатам** — заголовок комнаты (📍 + название), внутри — карточки оборудования.
- **Карточка задачи содержит:**
  - Название типа оборудования (жирный шрифт)
  - Адрес объекта + модель (серый текст, меньший шрифт)
  - Справа: иконка фото-прогресса (📷 2/2), статус-иконка, кнопка overflow-меню (⋮)
- **Пиктограммы статусов:**
  - ✅ «Выполнено» (зелёный)
  - 🔄 «В работе» (жёлтый/оранжевый)
  - ⚪ «Не начато» (серый)
  - **Рядом с иконкой — сокращённый текст статуса** для accessibility (см. §8)
- **Кнопка ⋮ (overflow menu)** — открывает действия: «Редактировать», «Удалить», «Перейти к фото». Является **основным способом** вызова действий на всех устройствах.

**Взаимодействие:**
- Тап по карточке → переход на TaskPage (открытие задачи).
- Свайп влево по карточке (опционально, только Android) → быстрый доступ к «Редактировать» / «Удалить».
- **iOS fallback:** свайп не используется (конфликт с PWA browser gesture). Вместо него — кнопка ⋮.

> **Реализация:** использовать `antd-mobile` компонент `SwipeAction` для Android. Для iOS и как fallback — `Dropdown` из `antd` с trigger `click`.

### 4.2. Страница задачи: TaskPage и GroupTaskPage

> *Добавлено по результатам ревью: это самые сложные формы в приложении, их адаптация требует отдельного описания.*

**Проблема:** TaskPage содержит динамическую форму, генерируемую на основе типа оборудования. Разные типы оборудования (ВиК, электрика, ИСЖ) имеют разные наборы полей. GroupTaskPage позволяет редактировать несколько единиц оборудования одновременно.

#### 4.2.1. TaskPage — адаптация формы

**Решение:**

1. **Вертикальная компоновка (Stacked Layout):** Label всегда располагается **над** полем ввода (уже используется `layout="vertical"` — сохранить).

2. **Секции (Accordion/Collapse):** Поля группируются в логические блоки с заголовками, каждый блок — сворачиваемый:
   - «Основные параметры» (всегда раскрыт)
   - «Параметры сети» (напряжение, ток, мощность)
   - «Состояние оборудования» (визуальный осмотр)
   - «Проведённые работы» (список выполненных действий)
   - «Рекомендации» (комментарии и замечания)

3. **Оптимизация Label:**
   - Сокращение длинных названий на мобильных (< 768px):
     - *Было:* «Состояние контактных соединений»
     - *Стало:* «Контактные соединения»
   - Полный текст доступен по long press (tooltip) или в выпадающем списке значений.

4. **Нативные пикеры (antd-mobile):**
   - На мобильных устройствах вместо `<Select>` из antd — использовать `Picker` из antd-mobile (Bottom Sheet Picker).
   - Типы полей с нативными пикерами: выбор оборудования, тип комнаты, статус, рекомендации.

5. **Таблица «Проведённые работы»** (внутри TaskPage):
   - На ПК: обычная таблица Ant Design.
   - На мобильных: трансформируется в список карточек:
     ```text
     ┌───────────────────────────────────┐
     │ Замена фильтра     25.07.2026  ⋮ │
     │ Чистка дренажа     25.07.2026  ⋮ │
     └───────────────────────────────────┘
     ```

#### 4.2.2. GroupTaskPage — групповая задача

**Проблема:** на экране отображается таблица с несколькими единицами оборудования и общими полями.

**Решение на мобильных:**
- **Tabs (вкладки)** для переключения между единицами оборудования (вместо таблицы).
- Общие поля (дата, статус, комментарии) — вверху страницы, вне вкладок.
- Переключение между вкладками — свайпом или тапом по названию оборудования.

### 4.3. Страница 5: «Фотофиксация» — PhotoPage, ItemPhotoPage

**Решение:**
- Кнопки «Сделать фото» и «Выбрать файл» располагаются друг под другом на всю ширину экрана (Full-width buttons).
- Превью фотографий отображаются в виде сетки 2×2 или 1×2 (в зависимости от ширины экрана), а не в одну строку.
- Использование атрибута `accept="image/*"` и `capture="environment"` для прямого вызова камеры.

> **Важно (iOS PWA):** атрибут `capture="environment"` **не поддерживается** в iOS Safari для PWA в режиме `standalone`. Необходимо реализовать fallback:
> - Показывать диалог выбора: «Сделать фото» / «Выбрать из галереи».
> - Для «Сделать фото» использовать `<input type="file" accept="image/*">` без `capture` — iOS предложит выбор камеры/галереи автоматически.

### 4.4. Навигация и Header

#### 4.4.1. Header (Шапка)

- **Мобильный Header ( < 768px):**
  - Слева: иконка «Назад» (←) или hamburger-меню (на главной).
  - Центр: сокращённое название страницы / адрес объекта (обрезается через `text-overflow: ellipsis`).
  - Справа: иконка профиля (👤), колокольчик уведомлений (🔔), кнопка фонарика (🔦, если доступна).
  - Адрес объекта: отображается город/улица, полный адрес — по тапу (раскрытие в tooltip или modal).

- **Планшет/ПК (≥ 768px):**
  - Полноценный Header с адресом объекта, навигацией, профилем.

#### 4.4.2. Bottom Navigation (нижняя панель навигации)

> *Добавлено по результатам ревью: необходим конкретный список вкладок и их состояний.*

**Область применения:** только для роли **Инженер** на мобильных устройствах (< 768px).

**Вкладки Bottom Navigation:**

| Вкладка | Иконка | Маршрут | Badge |
|---|---|---|---|
| Визиты | 📋 `UnorderedListOutlined` | `/` | — |
| Заявки | 📝 `FormOutlined` | `/my-requests` | Счётчик новых заявок |
| Отчёты | 📊 `BarChartOutlined` | `/reports/summary` | — |
| Профиль | 👤 `UserOutlined` | `/profile` | — |

**Состояния вкладки:**
- **Неактивная:** серая иконка + подпись (10px).
- **Активная:** синяя иконка (colorPrimary) + подпись, без фона.
- **Badge:** красный кружок с числом (макс. «99+») в правом верхнем углу иконки.

**Технические требования:**
- Высота панели: 56px + `env(safe-area-inset-bottom)`.
- Фон: белый, верхняя граница — `1px solid #f0f0f0`.
- При фокусе на поле ввода — панель **скрывается** (см. §6.2).
- Реализация: кастомный компонент `<BottomNav>` или `antd-mobile` `TabBar`.

### 4.5. Список визитов — VisitListPage

**Проблема:** Статистика (4 карточки в ряд через `Row/Col span={6}`) на узких экранах сжимается.

**Решение:**
- **Мобильный (< 768px):** статистика — горизонтальный скролл карточек (Carousel) или 2×2 сетка.
- **Список визитов:** уже использует карточки (`.visit-card`) — сохранить, улучшить:
  - Добавить статус-иконку и бейдж специализации (цветной).
  - Свайп для удаления (Android) или overflow-меню (⋮) на всех платформах.

## 7. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ К ВЕРСТКЕ И UI

### 7.1. Типографика и размеры

- **Масштабирование шрифтов через Ant Design токены**, а не CSS `clamp()`:
  ```typescript
  // ConfigProvider — кастомные токены для мобильных
  <ConfigProvider theme={{
    token: {
      fontSize: isMobile ? 14 : 16,
      fontSizeLG: isMobile ? 16 : 18,
      fontSizeSM: isMobile ? 12 : 14,
    }
  }}>
  ```
  > CSS `clamp()` несовместим с Ant Design token-системой и ломает внутреннюю логику компонентов.

- **Touch Targets:** Минимальный размер всех кликабельных элементов (кнопки, чекбоксы, иконки) — **44×44 px** (стандарт Apple HIG и Material Design).

- **Отступы:** Внутренние отступы (padding) карточек на мобильных устройствах сокращаются с 24px до 16px для экономии места.

### 7.2. Работа с клавиатурой на мобильных устройствах

- При фокусе на поле ввода (input/textarea) **Bottom Navigation скрывается**, чтобы клавиатура не перекрывала контент.
  - Определение через `visualViewport` API (основной способ).
  - **iOS fallback:** `resize` event listener на `window`, т.к. `visualViewport` на iOS Safari работает нестабильно в PWA.
  ```typescript
  // Основной способ
  window.visualViewport?.addEventListener('resize', () => {
    const isKeyboardOpen = window.visualViewport!.height < window.innerHeight * 0.75;
    setBottomNavVisible(!isKeyboardOpen);
  });

  // iOS fallback
  window.addEventListener('resize', () => {
    if (document.activeElement?.tagName === 'INPUT' || document.activeElement?.tagName === 'TEXTAREA') {
      setBottomNavVisible(false);
    }
  });
  ```

- Использование правильных атрибутов `inputmode`:
  - `inputmode="decimal"` — для полей с температурой, показаниями счётчиков.
  - `inputmode="numeric"` — для числовых кодов, ID.
  - `inputmode="tel"` — для телефонных номеров.
  - `inputmode="email"` — для email.

### 7.3. Производительность и анимации

- Отказ от тяжелых CSS-анимаций (например, параллакс) на мобильных устройствах для экономии батареи.
- Использование `will-change` только для критически важных анимаций (открытие модальных окон).
- Ленивая загрузка (Lazy Loading) изображений в списках визитов и избранного.
- **`antd-mobile` загружается динамически** (lazy import), чтобы не увеличивать бандл для десктопных пользователей:
  ```typescript
  const { Picker } = await import('antd-mobile');
  ```

## 8. ACCESSIBILITY (ДОСТУПНОСТЬ)

> *Добавлено по результатам ревью: пиктограммы без текста создают проблемы для пользователей с когнитивными нарушениями и screen reader.*

### 8.1. Требования

| # | Требование | Стандарт |
|---|---|---|
| 1 | Все иконки-статусы сопровождаются `aria-label` на русском языке. | WCAG 2.1 AA |
| 2 | Рядом с иконкой статуса отображается **сокращённый текст** (например, «✅ Выполн.»). | — |
| 3 | Контрастность текста и иконок — не менее 4.5:1 (для обычного текста), 3:1 (для крупного текста и иконок). | WCAG 2.1 AA |
| 4 | Все интерактивные элементы доступны с клавиатуры (Tab, Enter, Escape). | WCAG 2.1 AA |
| 5 | Модальные окна ловят фокус (focus trap) и возвращают его при закрытии. | WCAG 2.1 AA |
| 6 | Изображения (фото оборудования) имеют `alt` с описанием (тип оборудования + адрес). | WCAG 2.1 A |

### 8.2. Пример реализации статуса

```tsx
// Плохо: только иконка
<span>✅</span>

// Хорошо: иконка + текст + aria
<span role="status" aria-label="Выполнено" style={{ color: '#52c41a' }}>
  <CheckCircleOutlined /> <span className="status-text">Выполн.</span>
</span>
```

На мобильных (< 768px) текст сокращается до 1-2 символов или скрывается через CSS (`@media`), но `aria-label` остаётся для screen reader.

## 11. РИСКИ И ДОПУЩЕНИЯ

| Риск | Вероятность | Митигация |
|---|---|---|
| `antd-mobile` увеличивает bundle size | Средняя | Lazy import, tree-shaking. Мониторинг через bundle analyzer. |
| iOS Safari не поддерживает `capture="environment"` в PWA | Высокая | Fallback через стандартный file input (п. 4.3). |
| Свайп-жесты конфликтуют с PWA navigation | Высокая (iOS) | Кнопка ⋮ (overflow menu) как основной паттерн. Свайп — только на Android. |
| Service Worker кэширует старые CSS после обновления | Средняя | `skipWaiting` + `clientsClaim` в SW. Версионирование через Vite build hash. |
| `visualViewport` API нестабилен на iOS | Средняя | Fallback через `resize` listener (п. 7.2). |
