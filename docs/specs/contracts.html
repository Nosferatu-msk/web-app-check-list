Спецификация: Модуль договоров и сроки заявок

Привязка ТМ к договорам, изоляция данных, управление сроками, уведомления о просрочке
Версия: 1.1 Дата: 28.08.2026 Статус: На согласовании Модули: ТО + МТР Договора: 050005596590, 050001234567, 050007654321

1. Обзор и цели

На одном объекте могут работать разные подрядные организации (ТМ) с разными договорами. Необходимо обеспечить полную изоляцию данных: ТМ видит только свои заявки и визиты. Админ видит всё.

Бизнес-требования

IDТребованиеПриоритет
BR-1Привязка объекта к ТМ через договор (один объект — несколько ТМ с разными договорами)P0
BR-2Изоляция данных: ТМ видит только заявки/визиты по своим договорамP0
BR-3Импорт заявок с указанием номера договора, типа (плановая/внеплановая), даты началаP0
BR-4Автоматический расчёт сроков: плановая = календарный месяц, внеплановая = 14 дней (настраиваемо)P0
BR-5Уведомления за 5 дней до окончания срока (ТМ + инженеры)P1
BR-6Фильтр по периоду (месяц) в визитах и заявках + отображение просроченныхP1
BR-7Поиск по коду объекта, номеру заявки, адресу + фильтр по договоруP1
BR-8Бейдж договора в интерфейсе визитов и заявок (для всех ролей)P1
BR-9Расширение на модуль МТР (аналогичная логика)P2

Ограничения и допущения

Инженер = один ТМ. Инженер привязан к одному ТМ и работает только по его договорам. Модель TmEngineer не меняется.
Договор — простая сущность. Номер + ТМ-владелец. Без дат, сумм, контрагентов.

4. Логика сроков

4.1. Расчёт deadline при импорте

Тип заявкиДата в файлеstart_datedeadlineПример
Плановая 10.07.2026 01.07.2026 (1-е число месяца) 31.07.2026 (последний день месяца) Срок: весь июль
Внеплановая 11.07.2026 11.07.2026 (как в файле) 25.07.2026 (start + 14 дней) Срок: 14 дней
Настраиваемые сроки: Значения по умолчанию (месяц / 14 дней) задаются в таблице request_deadline_settings. Админ может изменить через админ-панель.

4.2. Уведомления о просрочке

Cron-задача (ежедневно, 08:00 МСК):

  1. Найти все заявки, где deadline - 5 дней ≤ today И status ≠ 'completed'
  2. Для каждой заявки: отправить уведомление ТМ (владельцу договора)
  3. Для каждой заявки: найти все связанные визиты через visit_requests и visit_engineers
  4. Отправить уведомление каждому назначенному инженеру

4.3. Просроченные заявки

Заявка считается просроченной, если deadline < today И статус не входит в ['completed', 'sent'].

9.3. Привязка существующих заявок

Контекст: Все существующие заявки в системе — плановые за август 2026. Следовательно: request_type = 'planned', start_date = '2026-08-01', deadline = '2026-08-31'. 
UPDATE imported_requests SET 
  contract_id = (
    SELECT c.id FROM contracts c
    JOIN tm_objects tmo ON tmo.address_id = imported_requests.matched_address_id
    WHERE c.tm_id = tmo.tm_id AND c.module = 'to'
    LIMIT 1
  ),
  request_type = 'planned',
  start_date = '2026-08-01'::date,
  deadline = '2026-08-31'::date
WHERE contract_id IS NULL;

9.4. Привязка существующих визитов

UPDATE visits v SET contract_id = (
  SELECT ir.contract_id FROM imported_requests ir
  JOIN visit_requests vr ON vr.imported_request_id = ir.id
  WHERE vr.visit_id = v.id
  LIMIT 1
)
WHERE v.contract_id IS NULL
  AND v.is_deleted = false;
Важно: Миграция выполняется в рамках деплоя. Существующие заявки без договора получают default-договор своего ТМ.
