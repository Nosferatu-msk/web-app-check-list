## 📐 Технические требования

### 1. Фильтр по критичности (десктоп)

**Компонент:** Сегментный контрол (Ant Design `Segmented` или кастомный)

**Параметры:**
- `Все` — показать все визиты с отклонениями (по умолчанию)
- `Критические` — показать только визиты с критическими отклонениями
- `Предупреждения` — показать только визиты с предупреждениями **И БЕЗ критических** (для массового подтверждения)

**Логика фильтра "Предупреждения":**
- Визит попадает в фильтр, если у него есть хотя бы одно предупреждение (severity='warning')
- **И** у визита нет ни одного критического отклонения (severity='critical')
- Это позволяет массово подтверждать только те визиты, которые требуют внимания, но не блокируются критическими проблемами

**Реализация:**
- Добавить состояние `severityFilter` (уже есть)
- Добавить UI-компонент в блок фильтров
- При изменении фильтра — сброс пагинации на страницу 1
- Отправлять параметр `severity` на сервер (уже поддерживается)

**Серверная поддержка:**
- ✅ Endpoint `GET /api/analytics/visits` уже поддерживает параметр `severity`
- ✅ Фильтрация реализована на сервере

### 2. Массовое подтверждение предупреждений

**Компонент:** Кнопка + модальное окно подтверждения

**Логика кнопки:**
- Показывается только если есть визиты с предупреждениями **без критических** (те, которые попадают в фильтр "Предупреждения")
- Текст кнопки: `Подтвердить все предупреждения (N визитов, M отклонений)`
- N — количество визитов с предупреждениями без критических
- M — общее количество предупреждений в этих визитах
- Кнопка скрывается, если фильтр "Предупреждения" показывает 0 визитов

**Логика модального окна:**
- Заголовок: `Подтверждение предупреждений`
- Статистика:
  - Визитов: N
  - Отклонений: M
  - Критические: 0 (не будут затронуты)
- Предупреждение: `Это действие нельзя отменить. Все предупреждения в выбранных визитах будут подтверждены.`
- Кнопки: `Отмена` | `Подтвердить`

**API endpoint:**
- Используется существующий `PATCH /api/analytics/anomalies/batch`
- Параметры: `{ anomalyIds: string[], status: 'confirmed' }`
- Клиент собирает ID всех предупреждений из визитов без критических и отправляет batch запрос

**Серверная логика (альтернатива — серверная функция):**
Дополнительно можно создать серверную функцию `confirmWarningsBatch()` в `analyticsService.ts` для упрощения клиента:
1. Найти все визиты за период с предупреждениями (без критических)
2. Собрать ID всех предупреждений
3. Обновить статус всех предупреждений на `confirmed`
4. Записать в audit_log: `Массовое подтверждение предупреждений: N визитов, M отклонений`
5. Вернуть статистику: `{ confirmed: number, visitsAffected: number }`

## 📊 Метрики успеха

- Время обработки одного визита сократится на 30% (не нужно открывать каждый визит)
- Количество кликов для подтверждения 10 визитов: 10 → 1 (массовое подтверждение)
- Пользовательский опыт: интуитивно понятно, быстро, безопасно

---

## ⚠️ Риски и ограничения

1. **Производительность:** При большом количестве визитов (>1000) массовое подтверждение может занять время
   - **Решение:** Добавить индикатор загрузки, ограничить количество визитов за раз (например, 500)

2. **Безопасность:** Массовое подтверждение нельзя отменить
   - **Решение:** Модальное окно с четким предупреждением, кнопка `Отмена`

3. **Консистентность:** Фильтр должен работать одинаково на мобильном и десктопе
   - **Решение:** Использовать один и тот же сегментный контрол
