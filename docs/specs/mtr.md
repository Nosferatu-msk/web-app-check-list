## 21. МОДУЛЬ «МЕЛКИЙ ТЕКУЩИЙ РЕМОНТ» (МТР)

> Раздел описывает модуль «Мелкий текущий ремонт» — самостоятельную подсистему для обработки заявок на ремонтные работы. Модуль использует отдельные таблицы, роли и API-роуты, не пересекающиеся с основным модулем ТО.

### 21.1. Назначение

Автоматизация работы инженеров МТР: выезд по заявке на мелкий ремонт, выполнение работ из утверждённого справочника, фотофиксация «до» и «после», формирование PDF-отчёта и отправка ТМ на согласование.

### 21.2. Роли

| Роль | Код | Описание |
|------|-----|----------|
| Инженер МТР | `engineer_mtr` | Выполняет выезд, заполняет работы, загружает фото, отправляет визит |
| Территориальный менеджер МТР | `tm_mtr` | Контролирует визиты подчинённых инженеров, принимает или отклоняет |
| Администратор | `admin` | Полный доступ: справочники, привязки ТМ, все визиты |

#### 21.3.6. Фотографии

Фотографии визитов МТР хранятся в общей таблице `photos` (раздел 3.2.8) через поле `mtr_visit_id` (FK → mtr_visits.id). Структура аналогична фотографиям ТО: момент съёмки `before` / `after`, маркировка файла, метаданные.

### 21.4. Статусная модель визита МТР

```
draft ──► in_progress ──► completed ──► sent ──► accepted
                                              └──► rejected
```

| Статус | Описание | Кто устанавливает |
|--------|----------|-------------------|
| `draft` | Черновик, данные не сохранены на сервере | Инженер (автоматически) |
| `in_progress` | Визит в работе, инженер на объекте | Инженер (при начале работ) |
| `completed` | Визит завершён, все условия выполнены | Инженер (при завершении) |
| `sent` | Отправлен ТМ на согласование | Инженер (после завершения) |
| `accepted` | Принят ТМ | ТМ МТР |
| `rejected` | Отклонён ТМ (с указанием причины) | ТМ МТР |

**Переходы:**

- **draft → in_progress** — инженер начинает заполнение работ / делает фото
- **in_progress → completed** — инженер нажимает «Завершить визит» (без модального подтверждения); выполняется автоматический переход на страницу отчёта
- **completed → sent** — инженер отправляет визит ТМ
- **sent → accepted / rejected** — ТМ принимает или отклоняет визит
- **completed → in_progress** — при сохранении визита в статусе `completed`, если условия завершения не выполнены (например, удалены работы или фото), статус автоматически возвращается в `in_progress`

### 21.5. API-контракты

Все маршруты модуля МТР используют префикс `/api/mtr`.

#### 21.5.1. Визиты (инженер МТР)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/visits` | Список визитов текущего инженера |
| POST | `/visits` | Создать визит |
| GET | `/visits/:id` | Получить визит по ID (с работами и фото) |
| PUT | `/visits/:id` | Обновить визит |
| DELETE | `/visits/:id` | Удалить визит (soft delete) |
| POST | `/visits/:id/works` | Добавить работу в визит |
| DELETE | `/visits/:id/works/:workId` | Удалить работу из визита |
| PUT | `/visits/:id/complete` | Завершить визит (статус → `completed`) |
| PUT | `/visits/:id/save-draft` | Сохранить визит; если условия завершения не выполнены — статус → `in_progress` |

#### 21.5.2. Визиты ТМ МТР

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/tm/visits` | Список визитов подчинённых инженеров |
| PUT | `/tm/visits/:id/accept` | Принять визит (статус → `accepted`) |
| PUT | `/tm/visits/:id/reject` | Отклонить визит (статус → `rejected`, требуется `rejectionReason`) |

#### 21.5.3. Администрирование МТР

| Метод | Путь | Описание |
|-------|------|----------|
| GET/POST/PUT/DELETE | `/admin/tm-objects` | CRUD привязок объектов к ТМ МТР |
| GET/POST/PUT/DELETE | `/admin/tm-engineers` | CRUD привязок инженеров МТР к ТМ МТР |
| GET/POST/PUT/DELETE | `/admin/work-types` | CRUD справочника видов работ МТР |

#### 21.5.4. Отчёты МТР

| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/api/reports/mtr/:id/report/generate` | Генерация PDF-отчёта визита МТР |
| GET | `/api/reports/mtr/:id/report/download` | Скачивание сгенерированного PDF |

### 21.6. Сценарий визита МТР

Полный сценарий работы инженера МТР на объекте:

```
1. Фото ДО          — фиксация исходного состояния (через камеру устройства)
2. Добавление работ  — выбор видов работ из справочника, указание количества
3. Фото ПОСЛЕ        — фиксация результата выполненных работ
4. Завершить визит   — статус → completed, автоматический переход на страницу отчёта
5. Страница отчёта   — просмотр сводки: адрес, работы, фото
6. Скачать ZIP       — архив содержит PDF-отчёт + все фотографии визита + Excel-таблицу оборудования
```

### 21.7. Офлайн-режим

Модуль МТР поддерживает полную работу без сетевого соединения:

- **Локальное хранилище** — все данные визитов, работ и фото сохраняются в IndexedDB через Dexie.js
- **Очередь синхронизации (sync queue)** — действия, выполненные офлайн (создание визита, добавление работ, загрузка фото), помещаются в очередь
- **Автоматическая синхронизация** — при восстановлении соединения очередь воспроизводится: данные отправляются на сервер в порядке поступления
- **Разрешение конфликтов** — при конфликте (например, визит удалён на сервере) пользователь получает уведомление

### 21.8. Отличия от модуля ТО

| Аспект | Модуль ТО | Модуль МТР |
|--------|-----------|------------|
| Назначение | Плановое техобслуживание | Мелкий текущий ремонт по заявке |
| Идентификатор заявки | — | `request_number` (номер заявки) |
| Единица работы | Задача (task) с параметрами оборудования | Работа (work) из справочника видов работ |
| Фотофиксация | По задачам (task_id) | По визиту (mtr_visit_id) |
| Роли | `engineer`, `tm` | `engineer_mtr`, `tm_mtr` |
| Привязки ТМ | `tm_objects`, `tm_engineers` | `mtr_tm_objects`, `mtr_tm_engineers` |
| Статусы визита | planned → in_progress → completed → sent → corrected_by_tm | draft → in_progress → completed → sent → accepted/rejected |
| API-префикс | `/api/visits`, `/api/tasks` | `/api/mtr` |
