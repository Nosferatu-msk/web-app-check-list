```
├─────────────────────────────────────────────┤
│  Проведённые работы:                        │
│  ┌─────────────────────────────────────────┐│
│  │   │ Внутр. блок СС    │ Серверная│📷2/2││ ✅ │

│  └─────────────────────────────────────────┘│
│                                             │

│                                             │
│  [✅ Завершить визит]                       │
└─────────────────────────────────────────────┘
```

**Логика элементов:**
- При открытии нового визита таблица «Проведённые работы» **пустая**
- Кнопка «+ Добавить оборудование» доступна сразу; для нового визита — автосохранение черновика при нажатии
- Клик на строку таблицы → переход на страницу параметров (4.x)
- Статусы: ⏳ Не начато / 🔄 В работе / ✅ Выполнено
- Прогресс фото: ⬜ нет / 📷 1/2 / 📷 2/2
- Кнопка «Завершить визит» неактивна, пока нет хотя бы 1 выполненной задачи

- Исключает записи, уже добавленные в визит (через `exclude_visit_id`)
- Кнопка «Добавить (N)» — массовое создание задач

### 7.7. Административный интерфейс

**Десктопный интерфейс** с боковым меню:

```
┌──────────┬──────────────────────────────────┐
│ Меню     │  Справочник адресов              │
│          │                                  │
│ 📍 Адреса│  [+ Добавить]  [🔍 Поиск...]    │
│ 🔧 Обо-  │  ┌─────────────────────────────┐ │
│    рудов.│  │ Адрес          │ Email      │ │
│ 🏠 Помещ.│  │ ───────────────┼────────── │ │
│ 📋 Рекомен│  │ ул. Тверская.. │ zak@...   │ │
│ 👤 Польз.│  │ ул. Хабаровская│ zak2@...  │ │
│ 📊 Аудит │  └─────────────────────────────┘ │
│ 📈 Мет-  │  ← 1 2 3 ... 10 →               │
│   рики   │                                  │
└──────────┴──────────────────────────────────┘
```

Каждый справочник — отдельная страница с CRUD-операциями.

**Раздел «Пользователи»** — таблица с колонками: ФИО, Email, Роль, **Спец.** (ВиК/ИСЖ/ГПМ/ДГУ/ИБП и их комбинации для инженеров, «—» для остальных), Активен. Строка поиска по ФИО и email (debounce 300ms, лимит 50). Модальное окно создания/редактирования включает блок «Специализация» (чек-боксы ВиК, ИСЖ, ГПМ, ДГУ, ИБП), отображаемый только при роли «Инженер». При открытии модального окна создания нового пользователя роль по умолчанию установлена в «Инженер» (`engineer`), поэтому блок «Специализация» отображается сразу при открытии формы создания (без необходимости сначала выбрать роль).

**Раздел «Сводные отчёты»** — форма с переключателем типа (за период / по объектам / по номерам заявок), обязательным диапазоном дат, мультивыбором объектов (Select mode="multiple"), поиском заявок по номерам (textarea + кнопка «Найти заявки»), опциональным фильтром по инженеру, drag-and-drop зоной для загрузки сканов актов (JPG/PNG/PDF, до 10 файлов, до 50 МБ). На мобильных устройствах переключатель типа отчёта отображается вертикально с сокращёнными подписями.

**Расширение UI отчётов — режим «По договору и периоду»:**
- **Переключатель режима:** «По договору и периоду» / «Указать номера заявок» — определяет способ формирования отчёта
- **Select для выбора договора** — список загружается через `api.getContracts()`
- При выборе режима «По договору и периоду» пользователь выбирает договор (Select) и указывает период дат
- **`contractId`** передаётся в `POST /api/reports/summary-generate` — сервер находит все заявки договора за указанный период и связанные с ними визиты
- При выборе режима «Указать номера заявок» — используется существующий механизм поиска по номерам (`search-by-numbers`)

### 7.9.1. Страница «Продуктовые метрики» (Администратор)

Маршрут: `/admin/metrics`. Данные рассчитываются по `audit_log`, исключая `login`.

```
┌──────────┬──────────────────────────────────────────────────────┐
│ ...      │  Продуктовые метрики        [7д | 30д | 90д]        │
│ 📊 Мет-  │  ┌──────┬──────┬──────┬──────┐                      │
│   рики   │  │ DAU  │ WAU  │ MAU  │ Ret. │                      │
│          │  │  12  │  28  │  45  │  78% │                      │
│          │  │ ср. 8│      │      │  ↑5% │                      │
│          │  └──────┴──────┴──────┴──────┘                      │
│          │                                                      │
│          │  📈 DAU по дням (LineChart)                          │
│          │     ╱\    ╱\                                         │
│          │    ╱  \  ╱  \    ╱\                                  │
│          │   ╱    \/    \  ╱  \                                 │
│          │                                                      │
│          │  ┌─────────────────┬────────────────────────┐        │
│          │  │ По ролям        │ Топ-10 действий        │        │
│          │  │ ■ Инж. 10 (83%) │ create      145  ████  │        │
│          │  │ ■ ТМ    1 (8%)  │ upload_photo 98  ███   │        │
│          │  │ ■ Адм.  1 (8%)  │ complete     67  ██    │        │
│          │  └─────────────────┴────────────────────────┘        │
└──────────┴──────────────────────────────────────────────────────┘
```

**Метрики:**
- **DAU** — уникальные пользователи сегодня + среднее за период
- **WAU** — уникальные пользователи за последние 7 дней
- **MAU** — уникальные пользователи за выбранный период
- **Retention** — % пользователей, активных вчера и сегодня
- **По ролям** — разбивка по engineer/tm/admin/engineer_mtr/tm_mtr (BarChart + список)
- **Топ-10 действий** — таблица с прогресс-барами и процентами

**API:** `GET /api/admin/metrics?period=30` — raw SQL к `audit_log` (WHERE action != 'login').

### 7.10. Баннер синхронизации (SyncBanner)

Отображается вверху экрана для авторизованных пользователей:
- **Офлайн** (оранжевый фон): «Офлайн-режим · Данные сохраняются локально»
- **Синхронизация** (голубой фон): спиннер + «Синхронизация... · N операций»
- **Ошибка** (красный фон): «Ошибка синхронизации» + кнопка «Повторить»
- **Есть несохранённые** (зелёный фон): «Онлайн · N ожидает» (клик → синхронизация)

### 7.11. Центр уведомлений

**Десктоп (Dropdown):**
- Выпадающий список из колокольчика 🔔 в шапке с бейджем непрочитанных
- Непрочитанные: фон `#f6f8ff`, жирный заголовок, цветная полоска слева (4px):
  - Синяя (`#1677ff`) — рабочие уведомления
  - Зелёная (`#52c41a`) — системные уведомления (`system_release`)
- Системные уведомления: бейдж/тег `NEW FEATURE` (зелёный, 10px)
- Кнопки внизу: «📖 Прочитать всё» и «🗑 Очистить»

**Мобильная версия (≤ 768px):**
- Fullscreen modal (Drawer на весь экран) вместо dropdown
- Кнопки «Прочитать всё» и «Очистить» — вертикально, на всю ширину
- Сокращённые подписи: «✓ Прочитано», «🗑 Очистить»

**Подтверждение очистки:** модальное окно с текстом «Все уведомления будут удалены из списка» и красной кнопкой «Очистить» (danger).

**Офлайн-режим:** список уведомлений кэшируется в IndexedDB (Dexie). При отсутствии сети отображаются кэшированные уведомления с пометкой «Офлайн». Действия ставятся в очередь синхронизации.
