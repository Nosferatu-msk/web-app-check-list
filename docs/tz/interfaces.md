## 5. ОПИСАНИЕ ИНТЕРФЕЙСОВ

### 5.1. Страница 1: «Визит» (Чек-лист задач)

**Поля:**
- 1.1. `Адрес объекта` — поиск по справочнику (обязательно)
- 1.2. `Дата начала` — дата (автозаполнение, обязательно)
- 1.3. `Время начала` — время (автозаполнение, обязательно)
- 1.4. `Сезон` — «Лето» / «Зима» (автоопределение по дате, доступно для редактирования)

**Таблица «Проведённые работы»:**

| Чекбокс | Вид оборудования | Помещение | Марка / Модель | Вложения | Статус |
|:-------:|------------------|-----------|----------------|:--------:|--------|
| ☐ | Климатическое оборудование | Серверная | 3 единицы | 📷 6/6 | Выполнено |
| ☐ | Климатическое оборудование | Клиентский зал | 2 единицы | 📷 3/4 | В работе |
| ☐ | Наружные блоки кондиционеров | Уровень объекта | 2 единицы | 📷 4/4 | Выполнено |
| ☐ | Прибор учета э/э | Электрощитовая | Меркурий 230 | 📷 1/1 | Выполнено |
| ☐ | РЩ/ГРЩ | Электрощитовая | ABB GS420 | ⬜ | Не начато |

> **Примечание:** Климатическое оборудование (внутренние блоки СС, МСС, VRV) группируется в одну задачу на помещение. Наружные блоки группируются в одну задачу на объект. Остальное оборудование — индивидуальные задачи.

**Кнопки:**
- `+ Добавить оборудование` — открывает модальное окно «Добавление оборудования» с двумя вкладками:
  - **Вкладка «📍 Уровень помещения»** — для оборудования с привязкой к помещению. Инженер выбирает помещение из списка, затем видит оборудование в нём (чекбокс-лист). Уже добавленные в визит единицы скрыты. При выборе помещения также отображается блок «Перенести из других помещений / уровня объекта» — оборудование из других помещений и без привязки к помещению, с кнопкой «Перенести» для смены привязки. Инженер может создать новое помещение и перенести в него любое оборудование объекта.
  - **Вкладка «➕ Добавить новое»** — форма для добавления оборудования, которого нет в привязке объекта:
    - Вид оборудования (выпадающий список из справочника)
    - Тип помещения (выпадающий список из справочника)
    - Комментарий (текстовое поле, необязательно)
    - Марка (текстовое поле, необязательно)
    - Модель (текстовое поле, необязательно)
    - Серийный номер (текстовое поле, необязательно)
    - Чекбокс «Предложить добавить в привязку объекта» (если отмечен — при сохранении создаётся предложение со статусом `pending` для утверждения администратором)
- `Завершить визит` — формирует PDF + ZIP (PDF + фото + Excel-таблица оборудования) (активна при наличии хотя бы 1 выполненной задачи)

**Мобильная адаптация модалки:** На мобильных устройствах (ширина экрана < 768px) вкладки модалки отображаются как сегментированный переключатель (Segmented) с сокращёнными метками: «Помещение» | «+ Новое». На десктопе — стандартные вкладки (Tabs).

**Логика:**
- При открытии нового визита таблица «Проведённые работы» **полностью пустая**. Никакое оборудование автоматически не подтягивается.
- Кнопка `+ Добавить оборудование` доступна сразу. Для нового (несохранённого) визита — при нажатии визит автоматически сохраняется как черновик, затем открывается модальное окно.
- При повторном нажатии «+ Добавить оборудование» во вкладках «Уровень помещения» и «Уровень объекта» отображаются только те единицы, которые инженер ещё не добавил в текущий визит.
- Если всё оборудование определённого уровня уже добавлено, соответствующая вкладка показывает сообщение «Всё оборудование уже добавлено в визит».
- Клик на строку таблицы открывает соответствующую страницу параметров (4.x)
- Кнопка «Завершить визит» неактивна, пока хотя бы одна задача не выполнена

> **Примечание:** Страница 2 «Объект контроля» и Страница 3 «Место установки» из исходного описания упразднены. Поля «Вид оборудования» и «Тип помещения» заполняются в модальном окне на Странице 1.

#### 5.2.0. Страница групповой задачи — Климатическое оборудование

Открывается при клике на строку «Климатическое оборудование» в чек-листе визита. Содержит **общие параметры** (один набор на все единицы) и **список единиц оборудования** с индивидуальными статусами и фото.

**Общие параметры:**

| № | Поле | Тип | Значения | По умолчанию | Обязательное |
|---|------|-----|----------|:------------:|:------------:|
| ГП-1 | Температура помещения на уровне 1,2м от пола | Number | °C | — | ✅ |
| ГП-2 | Заключение | Select | Исправно, замечаний нет / Исправно, есть замечания / Неисправно | Исправно, замечаний нет | ✅ |
| ГП-3 | Типовые рекомендации | Multi-checkbox | Из справочника (объединённый список по всем видам климата в задаче) | — | — |
| ГП-4 | Дополнительные рекомендации | Text | Свободный текст | — | Условно (обязательно при замечаниях или статусе «Не ОК» хотя бы одной единицы) |

**Список единиц оборудования:**

Для каждой единицы отображаются:
- Вид оборудования, марка, модель, серийный номер (из `object_equipment`)
- **Статус:** ✅ ОК / ⚠️ Не ОК (переключатель)
- **Фото ДО:** кнопка «📷 Сделать» / «🖼 Выбрать» + индикатор загрузки [x/2]
- **Фото ПОСЛЕ:** кнопка «📷 Сделать» / «🖼 Выбрать» + индикатор загрузки [x/2]

**Валидация:**
- Кнопка «Сохранить» активна всегда (после заполнения обязательных общих полей: температура, заключение)
- При сохранении система автоматически определяет статус задачи:
  - Все единицы имеют статус + фото → «Выполнено»
  - Хотя бы одна единица не заполнена → «В работе» (с сообщением «Не завершено единиц: N»)
- Инженер может сохранить неполную задачу и вернуться к ней позже
- При статусе «Не ОК» хотя бы одной единицы — поле «Дополнительные рекомендации» становится обязательным

**Защита от дубликатов фото:**
- **Серверная защита (SHA-256):** при загрузке фото сервер вычисляет SHA-256 хеш сжатого файла и проверяет:
  - Для **индивидуальных задач** — нет ли фото с таким же хешем среди других задач этого визита (жёсткий запрет, HTTP 409)
  - Для **групповых задач** — нет ли фото с таким же хешем среди других единиц оборудования в этой задаче (жёсткий запрет, HTTP 409)
- **Глобальная проверка (клиент):** перед загрузкой клиент вычисляет SHA-256 хеш сжатого файла и вызывает `POST /api/photos/check-duplicate` для проверки по всей БД
- При обнаружении дубликата — предупреждение: «Это фото уже используется инженером [Имя] в визите на [Адрес] для оборудования [Тип]. Вы уверены, что хотите загрузить его снова?»
- Инженер может подтвердить загрузку или отменить
- Хеш вычисляется **после сжатия** изображения, чтобы клиентский и серверный хеши совпадали
- Хеш сохраняется в БД (поле `hash` в таблице `photos`) для последующих проверок

**Кнопки:** `💾 Сохранить и вернуться в чек-лист` / `← Назад` / `🗑 Сбросить задачу`

> **Примечание:** Для групповой задачи наружных блоков структура аналогична, но вместо «Температура помещения» заполняются параметры наружных блоков: «Работоспособность», «Наличие утечек на трассах», «Наличие посторонних шумов».

### 5.3. Страница 5: «Фотофиксация»

**Макет:**
```
┌─────────────────────────────────────────────┐
│  Фотофиксация: [Вид оборудования]           │
│  Местоположение: [Тип помещения]            │
├─────────────────────────────────────────────┤
│  📷 Фото ДО выполнения работ:               │
│  [Сделать фото]  [Выбрать файл]             │
│  [Превью загруженного фото]                 │
├─────────────────────────────────────────────┤
│  📷 Фото ПОСЛЕ выполнения работ:            │
│  [Сделать фото]  [Выбрать файл]             │
│  [Превью загруженного фото]                 │
│  *(поле скрыто для оборудования с 1 фото)*  │
├─────────────────────────────────────────────┤
│  [Сохранить и вернуться в чек-лист]         │
│  [Назад]  [Сбросить задачу]                 │
└─────────────────────────────────────────────┘
```

**Логика:**
- Для оборудования, требующего 2 фото (СС, МСС, VRV, тепловая завеса, приточная установка, приточно-вытяжная установка, вытяжная установка): оба поля обязательны
- Для оборудования с 1 фото (РЩ, счетчики, сети): второе поле скрыто
- Кнопка «Сохранить» активна только после загрузки требуемого количества фото
- Кнопка «Сбросить задачу» очищает только текущую задачу
