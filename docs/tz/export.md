## 7. ТРЕБОВАНИЯ К ЭКСПОРТУ

### 7.1. Формирование PDF-отчета

**Структура документа:**

```
┌─────────────────────────────────────────────┐
│           АКТЫ ВЫПОЛНЕННЫХ РАБОТ            │
├─────────────────────────────────────────────┤
│ Общие сведения:                             │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ Адрес объекта:     г. Москва, ул. Тверская, │
│                    д.13                     │
│ Дата проведения:   02.07.2026              │
│ Время начала:      10:30                   │
│ Время окончания:   12:45                   │
│ Сезон:             Лето                    │
│ Инженер:           Иванов П.С.             │
├─────────────────────────────────────────────┤
│ 1. Внутренний блок СС (в серверной)         │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ 📍 Местоположение: Серверная                │
│ 🔧 Контролируемые параметры:                │
│    • Работоспособность: Удовлетворительно   │
│    • Наличие посторонних шумов: Нет         │
│    • Температура помещения: 18°C            │
│    • ...                                    │
│ 📸 Фотофиксация:                            │
│    [ФОТО 1] 01_splitvn_server_before        │
│    [ФОТО 2] 01_splitvn_server_after         │
│ ✅ Заключение: Исправно, замечаний нет      │
│ 📊 Рекомендации:                            │
│    • Выполнить чистку фильтров...           │
│    • Прочистить дренажную систему...        │
├─────────────────────────────────────────────┤
│ ...                                         │
├─────────────────────────────────────────────┤
│ ПОДПИСЬ ИНЖЕНЕРА: ____________ /Иванов П.С./│
└─────────────────────────────────────────────┘
```

**Расширение шапки визита в PDF-отчёте:**
- **Номер договора** — отображается в общем блоке сведений (если есть привязка к договору)
- **Номера заявок** — список номеров связанных заявок (из `visit_requests` и `importedRequests`)
- **Статус визита** — человекочитаемый статус (например, «Выполнено», «Отправлено»)

**Расширение данных задач в PDF-отчёте:**
- **Brand / model / serialNumber** для индивидуальных задач — отображаются в карточке задачи наряду с групповыми задачами (ранее показывались только для групповых задач)
- **Подсветка некорректных полей:** если поля `brand`, `model` или `serialNumber` содержат некорректные данные (определено антифрод-проверкой), они выделяются красным фоном (`#fff1f0`) в PDF-отчёте

**pHash-предупреждения в отчёте:**
- Если фото имеет отклонение типа `photo_phash_match` (критическое сходство с другим фото), в отчёте под таким фото размещается красная пометка «Дубликат»
- Пометка отображается только для ТМ/админа при формировании сводного отчёта

**Исключение виртуальных визитов:**
- Визиты без `userId` (виртуальные визиты, созданные из заявок со статусом `awaiting_assignment`) исключены из отчётов — они не содержат реальных данных работ

**Технические требования:**
- Формат: PDF/A-1b (для долгосрочного архивирования)
- Размер страницы: A4
- Шрифт: Arial / Roboto, 11pt
- Фотографии: встраиваются в PDF с разрешением 150 DPI
- Имя файла: `OTCHET_{street}_{house}_{date}.pdf`

### 7.2. Формирование ZIP-архива

**Структура архива:**
```
OTCHET_Tverskaya_13_02-07-2026.zip
├── OTCHET_Tverskaya_13_02-07-2026.pdf
├── OTCHET_Tverskaya_13_02-07-2026.xlsx
└── Photos/
    ├── 01_splitvn_server_12345678_before.jpg
    ├── 01_splitvn_server_12345678_after.jpg
    ├── 02_splitvn_server_12345679_before.jpg
    ├── 02_splitvn_server_12345679_after.jpg
    ├── 03_mssvn_server_45678901_before.jpg
    ├── 03_mssvn_server_45678901_after.jpg
    ├── 04_rsch_electroshc_nosn_before.jpg
    ├── 05_schetchik_electroshc_electroshc_98765432_before.jpg
    └── ...
```

**Excel-таблица оборудования** (`OTCHET_{street}_{house}_{date}.xlsx`):

Содержит сводную таблицу по всем задачам визита. Колонки:

| Колонка | Описание |
|---------|----------|
| Код объекта | Код объекта из адреса (справочник адресов) |
| Вид оборудования | Наименование типа оборудования |
| Серийный номер | Серийный номер единицы оборудования |
| Изготовитель | Марка (бренд) оборудования |
| Модель | Модель оборудования |
| Показания | Показания прибора учёта (заполняется **только** для счётчиков: `schetchik_electroshc`, `schetchik_gvs`, `schetchik_hvs`) |

- Для групповых задач (климатическое оборудование) каждая единица оборудования размещается в отдельной строке.
- Для индивидуальных задач каждая задача занимает одну строку.
- Колонка «Показания» заполняется только для приборов учёта; для остальных типов оборудования остаётся пустой.

**Шаблон имени файла:**
- Для индивидуальных задач: `{№}_{тип_оборудования}_{помещение}_{момент}.jpg`
- Для групповых задач (климат в помещении): `{№}_{тип_оборудования}_{помещение}_{серийный_номер}_{момент}.jpg`
- Для групповых задач (наружные блоки): `{№}_{тип_оборудования}_object_{серийный_номер}_{момент}.jpg`
- Если серийный номер отсутствует — используется `nosn`

> **Важно:** Все части имени файлаsanitize-ся — символы `/` и `\` заменяются на `_` для предотвращения создания поддиректорий.

**Имя архива:** `OTCHET_{street}_{house}_{date}.zip`

### 7.3. Отправка по email

**Требования:**
- Протокол: SMTP / SMTPS
- Размер вложения: до 25 МБ (при превышении — разбивка на несколько писем или использование облачного хранилища)
- Тема письма: `Акт выполненных работ: {full_address} от {date}`
- Тело письма: шаблон с краткой сводкой (адрес, дата, количество задач)
- Резервный сценарий: скачивание ZIP на устройство (PDF + фото + Excel-таблица)

### 7.4. Унифицированный сводный отчёт

**Структура документа (единая для отчёта за период и отчёта по объектам):**

```
┌─────────────────────────────────────────────┐
│        СВОДНЫЙ ОТЧЁТ ЗА ПЕРИОД              │
│        (или ОТЧЁТ ПО ОБЪЕКТАМ)              │
├─────────────────────────────────────────────┤
│ Период: 01.06.2026 — 30.06.2026            │
│ Дата формирования: 01.07.2026              │
│ Сформировал: Петрова А.В. (ТМ)             │
├─────────────────────────────────────────────┤
│ Статистика: визитов / задач / замечаний     │
├─────────────────────────────────────────────┤
│ ► Объект 1: г. Москва, ул. Тверская, д.13  │
│   ├─ Визит 1: 05.06.2026, Иванов П.С. (ВиК)│
│   │  ├─ Задача 1: Параметры, фото (превью),│
│   │  │  заключение, рекомендации            │
│   │  └─ Задача 2: ...                       │
│   └─ Визит 2: ...                           │
│ ► Объект 2: г. Москва, ул. Арбат, д.33     │
│   └─ ...                                    │
├─────────────────────────────────────────────┤
│ Приложения: Копии актов с подписью          │
│ (если загружены сканы)                      │
└─────────────────────────────────────────────┘
```

**Технические требования:**
- Генерация: `POST /api/reports/summary-generate` (унифицированный эндпоинт)
- Превью фото: `sharp` resize width=400px, quality=85, JPEG base64 inline
- Лимит фото: 200 штук; при превышении — упрощённый режим (текстовые метки)
- Сканы актов: сжатие изображений (width=1200px, quality=80), merge PDF через `pdf-lib`
- Титульный лист: название отчёта, период/объекты, дата, ФИО сформировавшего (из JWT)
- Имя файла: `Svodnyj_otchet_{dateFrom}_{dateTo}.pdf` или `Otchet_po_obektam_{dateFrom}_{dateTo}.pdf`

**UI формирования отчёта по договору (расширение интерфейса ТМ/Админа):**
- **Переключатель режима:** «По договору и периоду» / «Указать номера заявок» — позволяет выбрать способ формирования отчёта
- **Select для выбора договора** — загружается через `api.getContracts()`, список договоров из внешней системы
- При выборе режима «По договору и периоду»: пользователь выбирает договор и указывает период дат
- **`contractId`** передаётся в API `summary-generate` — сервер находит все заявки договора за указанный период и связанные с ними визиты
- При выборе режима «Указать номера заявок» — используется существующий механизм поиска по номерам (`search-by-numbers`)
