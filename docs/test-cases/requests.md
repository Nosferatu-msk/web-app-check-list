## TC-MOD-001: Inline-редактирование brand/model в карточке модерации

**Предусловие:** Администратор авторизован. В системе есть proposal с заполненными полями brand и model.
**Шаги:**
1. Открыть дашборд модерации (`GET /api/proposals/admin`)
2. Найти proposal с известными значениями brand/model
3. Нажать кнопку ✏️ рядом с полем «Изготовитель»
4. Изменить значение, нажать «Сохранить»
5. Повторить для поля «Модель»

**Ожидаемый результат:**
- Inline-редактирование работает (кнопка ✏️ → input → сохранить)
- Значения обновлены в proposal и в связанном `object_equipment`
- API `PATCH /api/proposals/:id` возвращает обновлённые данные

**Приоритет:** Высокий

## TC-MOD-003: Синхронизация brand/model из proposal в задачу при approve

**Предусловие:** Администратор авторизован. Есть proposal со статусом `pending`, связанный с задачей визита. Поля brand/model в proposal отличаются от значений в задаче.
**Шаги:**
1. Открыть дашборд модерации
2. При необходимости отредактировать brand/model inline (кнопка ✏️)
3. Утвердить proposal (`PUT /api/proposals/admin/:id/approve`)
4. Открыть задачу визита, связанную с proposal

**Ожидаемый результат:**
- Статус proposal изменён на `approved`
- В задаче визита поля brand/model/serialNumber содержат значения из proposal (с учётом изменений админа)
- Данные синхронизированы: proposal ↔ object_equipment ↔ task

**Приоритет:** Критический

## TC-MOD-004: Синхронизация brand/model при batch approve

**Предусловие:** Администратор авторизован. Есть несколько proposal со статусом `pending`, связанных с задачами визитов.
**Шаги:**
1. Открыть дашборд модерации
2. Выбрать несколько proposal (чекбоксы)
3. Нажать «Утвердить выбранные» (`PUT /api/proposals/admin/batch`)
4. Проверить задачи визитов для каждого утверждённого proposal

**Ожидаемый результат:**
- Все выбранные proposals утверждены (статус `approved`)
- Для каждого proposal данные brand/model/serialNumber синхронизированы в соответствующую задачу визита
- Массовое одобрение работает аналогично одиночному

**Приоритет:** Критический

- Панель фильтров: статус, тип запроса, инженер (с поиском), сортировка по дате (новые/старые), чекбокс «Истекают скоро»
- Массовые действия: чекбоксы на карточках, «Выбрать все», кнопки «Утвердить выбранные» / «Отклонить выбранные»

**Приоритет:** Высокий

### TC-REQ-001: Статус «Завершён» только при наличии задачи по типу оборудования

**Предусловие:** В системе есть импортированная заявка на оборудование «Прибор учёта э/э» (`schetchik_electroshc`). Заявка привязана к объекту RU/77/001.

**Шаги (негативный сценарий):**
1. Создать визит на объект RU/77/001 (заявка автоматически привязывается)
2. Добавить задачу с типом оборудования, **отличным** от типа заявки (например, «РЩ/ГРЩ»)
3. Заполнить параметры, загрузить фото, завершить визит
4. Проверить статус заявки

**Ожидаемый результат:** Статус заявки — **«Не назначена»**, поскольку в визите отсутствует задача по типу оборудования заявки.

**Шаги (позитивный сценарий):**
1. Создать второй визит, добавить задачу `schetchik_electroshc`
2. Завершить визит

**Ожидаемый результат:** Статус заявки — **«Завершён»**.
**Приоритет:** Критический
