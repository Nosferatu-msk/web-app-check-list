## TC-038: Офлайн-режим — PWA

**Шаги:**
1. Открыть приложение в Chrome
2. Открыть DevTools → Application → Service Workers
3. Проверить регистрацию SW
4. Переключить в режим Offline
5. Обновить страницу

**Ожидаемый результат:** Приложение загружается из кэша. Основной UI доступен.
**Приоритет:** Средний

## TC-039: Консоль браузера — отсутствие ошибок

**Шаги:**
1. Авторизоваться
2. Создать визит, добавить задачу, заполнить параметры, загрузить фото, сформировать отчёт
3. На каждом этапе проверять консоль браузера (F12)

**Ожидаемый результат:** В консоли НЕТ:
- `Warning: [antd: message] Static function can not consume context`
- Ошибок 401/404/500
- `date.isValid is not a function`
- Необработанных исключений

**Приоритет:** Критический

## TC-067: Soft delete — восстановление данных через аудит

**Предусловие:** Визит был удалён (soft delete).
**Шаги:**
1. Войти как администратор
2. Открыть журнал аудита
3. Найти записи с действием «delete» для визита

**Ожидаемый результат:** В журнале аудита отображается запись об удалении с указанием кто, когда и какой визит удалил. Данные визита доступны через прямой запрос к БД.
**Приоритет:** Средний

## TC-068: Офлайн — создание визита без сети

**Предусловие:** Инженер авторизован, сеть отключена (DevTools → Offline).
**Шаги:**
1. Открыть приложение — отображается баннер «Офлайн-режим»
2. Нажать «Новый визит»
3. Заполнить поля, нажать «Сохранить»

**Ожидаемый результат:** Визит создан и сохранён в IndexedDB. Сообщение «Визит сохранён локально». Визит отображается в списке. Баннер показывает «1 ожидает».
**Приоритет:** Критический

---

## TC-069: Офлайн — добавление задачи

**Предусловие:** Визит создан офлайн, сеть отключена.
**Шаги:**
1. Открыть визит
2. Нажать «Добавить оборудование»
3. На вкладке «Добавить новое» выбрать вид оборудования и помещение
4. Нажать «Добавить»

**Ожидаемый результат:** Задача добавлена в чек-лист локально. Статус «Не начато».
**Приоритет:** Критический

---

## TC-070: Офлайн — заполнение параметров

**Предусловие:** Задача создана офлайн.
**Шаги:**
1. Открыть задачу
2. Заполнить параметры
3. Выбрать заключение «Исправно, замечаний нет»
4. Нажать «Сохранить»

**Ожидаемый результат:** Параметры сохранены в IndexedDB. Задача в статусе «В работе».
**Приоритет:** Критический

## TC-071: Офлайн — загрузка фото

**Предусловие:** Задача создана офлайн.
**Шаги:**
1. Перейти к фотофиксации
2. Сделать фото (камера или галерея)

**Ожидаемый результат:** Фото сохранено как Blob в IndexedDB. Сообщение «Фото сохранено локально». Изображение отображается на экране.
**Приоритет:** Критический

## TC-072: Офлайн → Онлайн — автоматическая синхронизация

**Предусловие:** Созданы визит, задача, фото офлайн. В очереди синхронизации есть операции.
**Шаги:**
1. Включить сеть (DevTools → Online)
2. Наблюдать за баннером

**Ожидаемый результат:**
- Баннер меняется на «Синхронизация...»
- Визит создан на сервере (serverId заполнен)
- Задача создана на сервере
- Фото загружено на сервер
- Баннер меняется на «Онлайн»
- Очередь синхронизации пуста
**Приоритет:** Критический

## TC-073: Синхронизация — повтор при ошибке

**Предусловие:** Сервер временно недоступен (500 ошибка).
**Шаги:**
1. Восстановить сеть при недоступном сервере
2. Дождаться попытки синхронизации

**Ожидаемый результат:** Баннер показывает «Ошибка синхронизации». Кнопка «Повторить» активна. Операция остаётся в очереди (retryCount увеличивается).
**Приоритет:** Высокий

---

## TC-074: Баннер синхронизации — отображение статусов

**Предусловие:** Приложение открыто.
**Шаги:**
1. Отключить сеть — проверить баннер «Офлайн-режим» (оранжевый)
2. Включить сеть при наличии очереди — проверить «Синхронизация...» (голубой)
3. Дождаться завершения — проверить «Онлайн» (зелёный) или скрытие баннера

**Ожидаемый результат:** Баннер корректно отображает все три состояния с правильными цветами.
**Приоритет:** Высокий

## TC-075: PWA — кэширование API (NetworkFirst)

**Предусловие:** Приложение загружено, API-ответы закэшированы.
**Шаги:**
1. Отключить сеть
2. Выполнить запрос к API (например, получить список визитов)

**Ожидаемый результат:** Данные возвращаются из кэша Service Worker (NetworkFirst). Визиты отображаются.
**Приоритет:** Высокий

## TC-075.1: PWA — баннер обновления при деплое новой версии

**Предусловие:** Пользователь открыл приложение. На сервере задеплоена новая версия.
**Шаги:**
1. После деплоя новой версии перейти на вкладку с приложением (или обновить страницу один раз)
2. Дождаться проверки Service Worker (до 1 минуты)
3. Проверить появление баннера внизу экрана

**Ожидаемый результат:** Внизу экрана появляется синий баннер «Доступна новая версия приложения» с кнопками «Обновить» и «✕». Нажатие «Обновить» перезагружает страницу с новой версией. Нажатие «✕» скрывает баннер.
**Приоритет:** Высокий

---

## TC-075.2: Автообновление данных при возврате на вкладку

**Предусловие:** Пользователь находится на странице списка визитов.
**Шаги:**
1. Переключиться на другую вкладку браузера
2. На сервере изменить данные (например, создать визит через API)
3. Вернуться на вкладку с приложением
4. Подождать 1-2 секунды

**Ожидаемый результат:** Список визитов автоматически обновляется — новый визит появляется без ручного обновления страницы.
**Приоритет:** Высокий

---

## TC-075.3: Оборудование — загрузка без кэша при открытии модалки

**Предусловие:** Админ добавил новое оборудование к объекту. Инженер создаёт визит на этом объекте.
**Шаги:**
1. Инженер открывает визит на объекте, где было добавлено оборудование
2. Нажать «+ Добавить оборудование»
3. Перейти на вкладку «Уровень объекта» или «Уровень помещения»

**Ожидаемый результат:** Новое оборудование, добавленное админом, отображается в списке без необходимости перезагрузки страницы или повторного входа.
**Приоритет:** Высокий

## TC-098: Rate limiting — блокировка при множественных попытках входа

**Шаги:**
1. Попытаться войти 101 раз с неверным паролем в течение 15 минут

**Ожидаемый результат:** На 101-й попытке — ошибка «Слишком много попыток. Попробуйте через 15 минут.» (HTTP 429).
**Приоритет:** Средний
**Обновлено 14.09.2026:** Лимит составляет 100 запросов (не 21), подтверждено тестами.

## TC-301: API — корректные эндпоинты задач (подтверждено 14.09.2026)

**Предусловие:** Инженер авторизован, визит создан.
**Шаги:**
1. Вызвать `POST /api/visits/:visitId/tasks` с `equipmentTypeId` и `roomTypeId`
2. Вызвать `GET /api/visits/:visitId/tasks/:id`
3. Вызвать `PUT /api/visits/:visitId/tasks/:id` с параметрами
4. Вызвать `DELETE /api/visits/:visitId/tasks/:id`

**Ожидаемый результат:** Все 4 операции выполнены успешно (200/201). Эндпоинт `/api/tasks` (без visitId) возвращает 404.
**Приоритет:** Критический
**Статус:** ✅ Автоматизирован (API-TASK-1..6)

## TC-302: API — корректные эндпоинты фото (подтверждено 14.09.2026)

**Предусловие:** Задача создана.
**Шаги:**
1. Вызвать `POST /api/photos/:taskId/photos` с файлом и `moment=before`
2. Вызвать `POST /api/photos/:taskId/photos` с файлом и `moment=after`
3. Вызвать `GET /api/photos/:taskId/photos`
4. Вызвать `DELETE /api/photos/:id`

**Ожидаемый результат:** Фото загружены, список возвращает 2 записи, удаление успешно. Эндпоинт `POST /api/photos` (без taskId в URL) возвращает 404.
**Приоритет:** Критический
**Статус:** ✅ Автоматизирован (API-PHOTO-1..4)

## TC-303: API — обновление визита через PUT (подтверждено 14.09.2026)

**Предусловие:** Визит создан.
**Шаги:**
1. Вызвать `PUT /api/visits/:id` с `{ engineerName: "Новое имя" }`
2. Проверить, что `engineerName` обновлён
3. Попытаться вызвать `PATCH /api/visits/:id` — проверить ответ

**Ожидаемый результат:** PUT возвращает 200 с обновлёнными данными. PATCH возвращает 404 (не поддерживается). Схема принимает только: addressId, engineerName, dateStart, timeStart, season.
**Приоритет:** Высокий
**Статус:** ✅ Автоматизирован (API-VIS-7)

## TC-304: API — завершение визита через /complete (подтверждено 14.09.2026)

**Предусловие:** Визит создан, есть хотя бы одна выполненная задача с фото.
**Шаги:**
1. Вызвать `POST /api/visits/:id/complete`
2. Проверить статус визита

**Ожидаемый результат:** Статус изменён на `completed`, `timeEnd` заполнен. Без выполненных задач — HTTP 400.
**Приоритет:** Критический

## TC-305: API — поиск адресов через /search (подтверждено 14.09.2026)

**Предусловие:** Инженер авторизован.
**Шаги:**
1. Вызвать `GET /api/refs/addresses/search?q=ад`
2. Проверить результат

**Ожидаемый результат:** Массив адресов, отфильтрованных по вхождению "ад" в fullAddress/street/objectCode. Эндпоинт `/api/refs/addresses?search=` возвращает 404.
**Приоритет:** Критический
**Статус:** ✅ Автоматизирован (API-REF-3)

## TC-306: Тестовая учётка — верификация (14.09.2026)
