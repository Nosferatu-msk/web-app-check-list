# Публикация в Google Play — Пошаговая инструкция

## Предварительные требования

| Требование | Статус |
|---|---|
| Expo account (ipbaydachenko@mail.ru) | ✅ Есть |
| EAS CLI установлен | `npm install -g eas-cli` |
| Google Play Developer Account ($25) | ⬜ Нужно зарегистрировать |
| Firebase Project (для push) | ⬜ Нужно создать |
| Keystore для подписи | ⬜ Создастся автоматически |

---

## Шаг 1: Регистрация Google Play Developer Account

1. Перейти на https://play.google.com/console
2. Оплатить единоразовый взнос $25
3. Заполнить профиль разработчика:
   - Имя разработчика: **«Чек-лист инженера»**
   - Email для связи
   - Адрес (можно домашний)
4. Верификация занимает 1-3 дня

---

## Шаг 2: Настройка Firebase (для push-уведомлений)

1. Создать проект на https://console.firebase.google.com
2. Добавить Android-приложение с package: `ru.checkonout.mobile`
3. Скачать `google-services.json` → положить в `mobile/`
4. В Firebase Console → Cloud Messaging → скопировать **Server Key**
5. Добавить Server Key в серверное приложение (PWA) для отправки push

---

## Шаг 3: Сборка production AAB

```bash
cd mobile

# Логин в EAS
eas login

# Сборка production AAB (Android App Bundle)
eas build --platform android --profile production

# Или с локальной сборкой:
eas build --platform android --profile production --local
```

**Результат:** `.aab` файл для загрузки в Google Play.

---

## Шаг 4: Загрузка в Google Play Console

### 4.1 Создание приложения

1. Google Play Console → **Создать приложение**
2. Название: **Чек-лист инженера**
3. Язык по умолчанию: **Русский**
4. Тип приложения: **Приложение**
5. Бесплатное/Paid: **Бесплатное**

### 4.2 Описание для магазина

**Краткое описание (80 символов):**
```
Цифровой чек-лист для инженеров ТО. Визиты, параметры, фото, отчёты. Офлайн.
```

**Полное описание:**
```
«Чек-лист инженера» — мобильное приложение для автоматизации работы инженеров по техническому обслуживанию оборудования.

🔧 ОСНОВНЫЕ ФУНКЦИИ:
• Создание визитов с привязкой к адресу и GPS-координатам
• 35+ типов оборудования с параметрами (РЩ, вентиляция, кондиционеры, счётчики, сети)
• Фотофиксация ДО/ПОСЛЕ с автоматическим сжатием
• Генерация PDF-отчётов и отправка заказчику
• Голосовой ввод примечаний

📱 ОФЛАЙН-РЕЖИМ:
• Полная работа без интернета (подвалы, серверные, удалённые объекты)
• Автоматическая синхронизация при появлении сети
• Кеширование справочников на устройстве

🔐 БЕЗОПАСНОСТЬ:
• Вход по биометрии (отпечаток/лицо) или PIN-коду
• Автоматическая блокировка через 5 минут неактивности
• Предупреждение 152-ФЗ при фотофиксации

📊 ТИПЫ ОБОРУДОВАНИЯ:
• РЩ/ГРЩ — распределительные щиты
• Вентиляционные установки (приточные, вытяжные, VRV, МСС, СС)
• Приборы учёта (э/э, ХВС, ГВС, газ)
• Сети водоснабжения и тепловые сети
• Котлы, ИТП, ДГУ, ИБП, лифты и др.

Приложение является дополнением к веб-версии «Цифровой чек-лист инженера» и работает с единым сервером.
```

### 4.3 Скриншоты

Необходимо загрузить минимум **2 скриншота** (рекомендуется 4-8):

| # | Экран | Что показать |
|---|---|---|
| 1 | Список визитов | Карточки визитов с бейджами, прогресс-баром |
| 2 | Параметры задачи | Форма с сегментированными кнопками, чекбоксы рекомендаций |
| 3 | Камера | Экран съёмки с фонариком, переключением камеры |
| 4 | Отчёт | PDF-просмотр, кнопка «Отправить» |
| 5 | Профиль | Аватар, биометрия, переключатель темы |

**Требования Google Play:**
- Формат: PNG или JPEG
- Размер: мин. 1080px по меньшей стороне, макс. 8000px
- Соотношение: 16:9 или 9:16
- Без рамки устройства на скриншоте

### 4.4 Иконка приложения

- **Store listing icon:** 512×512 PNG (already exists: `assets/icon.png`)
- **Adaptive icon:** already configured in app.json

### 4.5 Категория и контент

- Категория: **Бизнес** или **Инструменты**
- Тег: **Производительность**
- Возрастной рейтинг: **Для всех** (IARC questionnaire)

### 4.6 Политика конфиденциальности

Обязательно указать URL политики конфиденциальности. Можно использовать:
- GitHub Pages с markdown-файлом
- Google Sites
- Любой хостинг

Минимальное содержание:
- Какие данные собираются (GPS, фото, email)
- Как хранятся (SQLite на устройстве + сервер)
- 152-ФЗ согласие на обработку персональных данных
- Контакты для обратной связи

## Шаг 6: Публикация

### 6.1 Production Track

1. Google Play Console → Приложение → Production
2. Загрузить AAB
3. Заполнить все обязательные поля:
   - Описание, скриншоты, иконка
   - Политика конфиденциальности
   - Возрастной рейтинг (IARC)
   - Декларация контента
4. Отправить на проверку

### 6.2 Время проверки

- Первая публикация: **3-7 дней**
- Обновления: **1-3 дня**
- Срочные обновления (security): **несколько часов**

---

## Шаг 7: OTA-обновления (EAS Update)

После публикации обновления JS-бандла можно доставлять без Google Play:

```bash
# Публикация OTA-обновления
eas update --branch production --message "Исправление бага"
```

**Когда использовать:**
- Исправление багов
- Небольшие улучшения UI
- Обновление текстов

**Когда нужна новая сборка:**
- Изменение нативных модулей (камера, GPS)
- Обновление Expo SDK
- Изменение permissions

## Версионирование

| Поле | Формат | Пример |
|---|---|---|
| version (app.json) | `MAJOR.MINOR.PATCH` | `1.0.0` |
| versionCode (Android) | Авто-инкремент | `1`, `2`, `3`... |

- **MAJOR:** значительные изменения (новый дизайн, breaking changes)
- **MINOR:** новые функции
- **PATCH:** исправления багов
