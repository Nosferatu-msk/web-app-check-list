## Реализованный функционал

### Новый отчёт по заявкам (PDF)

**Структура:**
1. **Титульный лист** — название, период, дата формирования, ФИО
2. **Сводные KPI** — 8 показателей (заявки, визиты, задачи, объекты, SLA)
3. **Детализация по заявкам** — по одному листу на заявку с визитами
4. **Заявки без визитов** — одна таблица в конце (не отдельные листы)

**KPI:**
- Общее количество заявок
- Завершены / В работе / Не начаты
- SLA: (закрытые в срок / общее количество заявок) × 100%
- Количество совершённых визитов
- Количество выполненных задач
- Количество обслуженных объектов

## Выявленные и исправленные проблемы

### 1. Расхождение статистики между ролями (Админ vs ТМ)

**Проблема:** ТМ видел 113 заявок, Админ видел 132 заявки.

**Корень:** Фильтрация ТМ в RequestsPage проверяла `visit.visitEngineers`, но 91 заявка из 132 имела визиты без `visitEngineers`. Эти заявки не видны ТМ.

**Исправление:** Убрана фильтрация по `visitEngineers` для ТМ. ТМ теперь видит все заявки своего договора.

**Коммит:** `05a43f5`

---

### 2. Неправильное определение статусов заявок ИСЖ объекта

**Проблема:** Все 132 заявки определялись как "В работе" (Завершены=0, В работе=132, Не начаты=0).

**Корень:** Все заявки имеют `equipmentTypeCode = 'iszh_object'`, но задачи в визитах имеют другие типы оборудования. Проверка `hasMatchingTask` никогда не проходила.

**Исправление:** Добавлена отдельная логика для ИСЖ объекта — агрегированный статус по всем визитам без проверки `hasMatchingTask`.

**Коммит:** `41a00b6`

---

### 3. Неправильное распределение статусов (assigned → in_progress)

**Проблема:** В отчёте "В работе" = 82, а должно быть 6. "Не назначенные" = 0, а должно быть 76.

**Корень:** В коде `assigned` (назначенные) маппились в `in_progress` (в работе).

**Исправление:** `assigned` теперь маппится в `not_started` (не назначенные).

**Коммит:** `7df8be1`

---

### 4. Неправильный расчёт SLA

**Проблема:** SLA = 100% (50 закрытых в срок / 50 закрытых × 100%).

**Корень:** SLA рассчитывался только по закрытым заявкам.

**Исправление:** SLA = (закрытые в срок / общее количество заявок) × 100%. Теперь SLA = 50 / 132 × 100% = 37.9%.

**Коммит:** `7df8be1`

---

### 5. Дубликаты фото не обозначаются в отчёте

**Проблема:** В модуле антифрод есть дубликаты, но в отчёте они не обозначены.

**Корень:** В коде искали `type = 'duplicate'`, но дубликаты помечаются как `photo_phash_match` с `severity = 'critical'`.

**Исправление:** Добавлен запрос по обоим типам: `duplicate` И `photo_phash_match` с `severity = 'critical'`.

**Коммит:** `157e2f0`

---

### 6. Отдельные листы для заявок без визитов

**Проблема:** Для каждой заявки без визитов создавался отдельный лист с текстом "Нет визитов по заявке".

**Корень:** В коде не было разделения заявок с визитами и без визитов.

**Исправление:** Заявки без визитов собираются в одну таблицу на одном листе (столбцы: №, Номер заявки, Адрес, Статус).

**Коммит:** `157e2f0`

## Ключевые бизнес-правила

### 1. Заявка ИСЖ объекта
Заявка ИСЖ объекта означает обслуживание **ВСЕГО** оборудования объекта, а не конкретного типа. Поэтому:
- `equipmentTypeCode = 'iszh_object'` у заявки
- Задачи имеют конкретные `equipmentTypeId` (Внутренний блок СС, Прибор учета ХВС, и т.д.)
- **Нельзя проверять** `hasMatchingTask` для ИСЖ объекта
- Статус определяется по **всем визитам** (агрегированный статус)

### 2. Фильтрация ТМ
ТМ видит **все заявки своего договора**, а не только назначенные инженерам. Это соответствует бизнес-логике:
- ТМ может создавать визиты самостоятельно (без инженеров)
- ТМ является частью команды, которую возглавляет
- ТМ должен контролировать все заявки на своей территории
- Фильтрация по `contractId` уже ограничивает доступ ТМ только своими договорами

### 3. Расчёт SLA
SLA = (Заявки, закрытые в срок / **Общее количество заявок**) × 100%

Это означает, что незавершённые заявки **уменьшают** SLA, что мотивирует команду завершать заявки в срок.

### 4. Дубликаты фото
Дубликаты помечаются как:
- `type = 'duplicate'` (устаревший)
- `type = 'photo_phash_match'` с `severity = 'critical'` (текущий)

В отчёте обозначаются **оба типа** дубликатов.

### 5. Заявки без визитов
Заявки без визитов (не назначенные) собираются в **одну таблицу** в конце отчёта, а не отображаются на отдельных листах. Это экономит место и упрощает восприятие.
