# Диагностика и исправление синхронизации оборудования с помещениями

## Проблема

**Выявлена:** 12.10.2026  
**Объект:** RU/77/617 (и потенциально другие)

Инженер во время визита распределяет оборудование по помещениям, но изменения не сохраняются в справочнике `ObjectEquipment`. При следующем визите инженера оборудование снова отображается в старом помещении.

## Корень проблемы

**Файл:** `client/src/pages/VisitPage.tsx`  
**Строка:** 549 (до исправления)

**Баг:** Для не-климатического оборудования `room_change` proposal создавался **ТОЛЬКО** если оборудование не имело `roomTypeCode` (находилось на "уровне объекта").

```typescript
// НЕПРАВИЛЬНО (до исправления)
if (!eq.roomTypeCode && targetRoomTypeCode) {
  await api.createRoomChangeProposal({ ... });
}
```

**Исправление:**
```typescript
// ПРАВИЛЬНО (после исправления)
if (eq.roomTypeCode !== targetRoomTypeCode && targetRoomTypeCode) {
  await api.createRoomChangeProposal({ ... });
}
```

## Что исправлено

✅ **Код исправлен** — условие создания `room_change` proposal теперь корректное  
✅ **Диагностический скрипт создан** — `server/scripts/diagnose-room-sync.ts`

## Дополнительные проверки

### Проверить конкретный объект

```sql
-- Подключиться к БД
docker compose -f docker-compose.prod.yml exec -T db psql -U checklist -d checklist

-- Найти все proposals для объекта
SELECT ep.id, ep.status, ep.request_type, ep.room_type_code, 
       oe.room_type_code as equipment_room, a.object_code
FROM equipment_proposals ep
JOIN addresses a ON a.id = ep.address_id
LEFT JOIN object_equipment oe ON oe.id = ep.object_equipment_id
WHERE a.object_code = 'RU/77/617'
ORDER BY ep.created_at DESC;

-- Найти рассинхронизации для объекта
SELECT t.id as task_id, t.room_type_code as task_room,
       oe.room_type_code as equipment_room, oe.id as equipment_id
FROM tasks t
JOIN object_equipment oe ON oe.id = t.object_equipment_id
JOIN visits v ON v.id = t.visit_id
JOIN addresses a ON a.id = v.address_id
WHERE a.object_code = 'RU/77/617'
  AND t.room_type_code != oe.room_type_code;
```

## Архитектурные выводы

**Проблема:** Клиентская логика создания proposals не учитывала сценарий "перенос из помещения A в помещение B".

**Решение:** Изменить условие с `!eq.roomTypeCode` на `eq.roomTypeCode !== targetRoomTypeCode`.

**Урок:** При реализации бизнес-логики необходимо учитывать ВСЕ сценарии:
1. Оборудование с уровня объекта → в помещение ✅
2. Оборудование из помещения A → в помещение B ❌ (был баг)
3. Оборудование уже в целевом помещении → пропустить ✅
