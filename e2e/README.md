# Модуль автоматического тестирования (E2E)

Автоматические end-to-end тесты на базе **Playwright**.

## Быстрый старт

```bash
# Запуск всех тестов
npm run test:e2e

# Запуск с UI (интерактивный режим)
npm run test:e2e:ui

# Просмотр отчёта после запуска
npm run test:e2e:report

# Запуск перед деплоем (с отчётом)
npm run test:pre-deploy

# Запуск тестов на production-сервере
npx playwright test --config=playwright.config.prod.ts
```

## Структура тестов

```
e2e/
├── auth.spec.ts                    — TC-001..003: Авторизация
├── visits.spec.ts                  — TC-004..006: Создание визитов
├── admin.spec.ts                   — Админ-панель, меню, breadcrumbs
├── admin-extended.spec.ts          — Расширенные тесты админки (оборудование, адреса)
├── ui-redesign.spec.ts             — Проверка UI-редизайна (P0-P3)
├── visit-complete-bug.spec.ts      — Тесты завершения визита (баги)
├── visit-complete-existing.spec.ts — Тесты завершения существующего визита
├── visit-command-visibility.spec.ts — TC-VIS-COMMAND: Видимость визитов команды
├── visit-editing-lock.spec.ts      — TC-VIS-LOCK: Блокировка редактирования
└── engineer.spec.ts                — Тесты инженера
```

## Новые тесты (07.10.2026)

### Видимость визитов команды для инженеров

**TC-VIS-COMMAND-001: Инженер видит визиты коллег по команде**
- Инженер А создаёт визит
- Инженер Б (из той же команды ТМ) видит визит инженера А
- Визит отображается с пометкой "Визит коллеги"

**TC-VIS-COMMAND-002: Пометка "Визит коллеги" отображается**
- Проверка наличия оранжевого тега "Визит коллеги" в списке визитов
- Пометка отображается только для визитов других инженеров из команды

**TC-VIS-COMMAND-003: Инженер не может удалить чужой визит**
- Инженер пытается удалить визит коллеги
- Появляется ошибка "Вы можете удалять только свои визиты"

### Блокировка одновременного редактирования

**TC-VIS-LOCK-001: Блокировка устанавливается при открытии визита**
- Инженер открывает визит → устанавливается блокировка
- Проверяется наличие предупреждения "Визит коллеги"

**TC-VIS-LOCK-002: Предупреждение при попытке открыть заблокированный визит**
- Инженер А открывает визит
- Инженер Б пытается открыть тот же визит
- Появляется предупреждение "Визит в настоящее время редактируется инженером..."

**TC-VIS-LOCK-003: Завершённый визит нельзя редактировать**
- Инженер открывает завершённый визит
- Появляется ошибка "Визит завершён или отправлен и не может быть изменён"

## Требования

- Node.js 18+
- Запущенные серверы: `docker compose up -d` + `cd server && npm run dev` + `cd client && npm run dev`
- Или Playwright запустит клиент автоматически через `webServer` в конфиге

## Добавление новых тестов

1. Создайте файл `e2e/<имя>.spec.ts`
2. Используйте `test.describe` для группировки
3. Для авторизации используйте `beforeEach` с логином
4. Добавляйте комментарии с номером тест-кейса (TC-XXX)

## CI/CD (будущее)

Для интеграции в CI добавьте в GitHub Actions:

```yaml
- name: Run E2E tests
  run: |
    docker compose up -d
    cd server && npm run dev &
    cd client && npm run dev &
    npx playwright test
```

## Тестирование на production

Для запуска тестов на production-сервере (https://checkonout.ru):

```bash
npx playwright test --config=playwright.config.prod.ts
```

**Важно:**
- Тесты запускаются на реальном production-сервере
- Используется HTTPS с игнорированием ошибок сертификатов
- Тесты не влияют на реальные данные (только чтение)

## Отладка тестов

Для отладки используйте UI-режим:

```bash
npm run test:e2e:ui
```

Это откроет интерактивный интерфейс Playwright, где можно:
- Запускать тесты по одному
- Видеть действия в реальном времени
- Делать скриншоты
- Анализировать ошибки
