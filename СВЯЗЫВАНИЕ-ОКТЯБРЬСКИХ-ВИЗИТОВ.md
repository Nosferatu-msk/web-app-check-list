# Связывание октябрьских визитов с заявками

## Проблема

Визиты, созданные в октябре вручную (без автопривязки), не связаны с заявками октября через таблицу `VisitRequest`.

**Симптомы:**
- Инженеры не видят заявки в отчётах ТМ
- ТМ не может отследить выполнение заявок октября
- Отчёты по договорам показывают неполные данные
- В сводных отчётах визиты без заявок не учитываются

**Причина:**
При создании визита инженером автопривязка работает только для заявок ИСЖ объекта. Если визит создан вручную (без модального окна подтверждения заявок), связь с заявками не устанавливается.

## Решение

### 1. Запуск скрипта связывания (разовое исправление)

**На Windows (локальная разработка):**
```bash
# Из корня проекта
scripts\link-october-visits.bat
```

**На production (Linux):**
```bash
# Из корня проекта на сервере
cd /path/to/web-app-check-list
docker compose -f docker-compose.prod.yml exec -T server npx tsx scripts/link-october-visits-to-requests.ts
```

**Что делает скрипт:**
1. Находит все визиты октября (01.10.2026 - 31.10.2026), не имеющие привязок
2. Для каждого визита ищет подходящие заявки:
   - **ИСЖ объект**: по адресу и периоду действия заявки
   - **Конкретное оборудование**: по адресу, типу оборудования (из задач визита) и периоду
3. Создаёт связи в таблице `visit_requests`
4. Обновляет `imported_requests.visit_id`
5. Синхронизирует `contract_id` из заявки в визит
6. Логирует все действия в `request_assignment_log`

### 2. Проверка результата

**SQL запрос для проверки:**
```sql
-- Визиты октября с количеством привязанных заявок
SELECT 
  v.id AS visit_id,
  v.date_start,
  a.object_code,
  a.full_address,
  COUNT(vr.id) AS linked_requests_count
FROM visits v
JOIN addresses a ON a.id = v.address_id
LEFT JOIN visit_requests vr ON vr.visit_id = v.id
WHERE v.date_start >= '2026-10-01' 
  AND v.date_start < '2026-11-01'
  AND v.is_deleted = false
GROUP BY v.id, v.date_start, a.object_code, a.full_address
ORDER BY v.date_start;
```

**Ожидаемое поведение:**
- Все визиты октября должны иметь `linked_requests_count > 0`
- Если визит не имеет привязок — значит, для него не найдено подходящих заявок

### 3. Улучшения в коде (автоматическая привязка будущих визитов)

Помимо скрипта, улучшена логика автопривязки в `server/src/routes/visits.ts`:

**При создании визита (`POST /api/visits`):**
- Автопривязка заявок ИСЖ объекта по адресу и периоду
- Назначение инженера на заявку
- Логирование в `request_assignment_log`

**При завершении визита (`POST /api/visits/:id/complete`):**
- Автопривязка заявок ИСЖ объекта (если ещё не привязаны)
- Автопривязка заявок на конкретное оборудование (по типам задач визита)
- Синхронизация `contract_id` из заявки в визит

**Как это работает:**
1. Инженер создаёт визит по адресу → система проверяет наличие заявок ИСЖ объекта
2. Если найдены — показывает модальное окно с предложением привязать заявки
3. Инженер подтверждает → создаются связи `VisitRequest`
4. При завершении визита — дополнительная проверка и привязка заявок на конкретное оборудование

## Бизнес-правила

### ИСЖ объект
Заявка на ТО ИСЖ объекта означает обслуживание **ВСЕГО** оборудования объекта (ВИК, ИСЖ, ДГУ, ИБП). 

**Пример:**
- Заявка: `ISZH-2026-10-001` на объект "Москва, Ленина, 1"
- Инженер 1 (ВИК): создаёт визит → привязывается к `ISZH-2026-10-001`
- Инженер 2 (ИСЖ): создаёт визит → привязывается к `ISZH-2026-10-001`
- Инженер 3 (ДГУ): создаёт визит → привязывается к `ISZH-2026-10-001`
- Все три визита связаны с одной заявкой

### Конкретное оборудование
Заявка на конкретное оборудование (например, `splitvn` — внутренний блок сплит-системы) привязывается к **одному** визиту, который содержит задачу с соответствующим типом оборудования.

**Пример:**
- Заявка: `REQ-2026-10-005` на `splitvn` для объекта "Москва, Ленина, 1"
- Инженер создаёт визит, добавляет задачу `splitvn`
- При завершении визита — заявка привязывается к этому визиту
- Другой визит на этот же адрес не может привязаться к этой заявке

## Технические детали

### Таблица `visit_requests`
Промежуточная таблица для связи "визит ↔ заявка" (многие-ко-многим):

```sql
CREATE TABLE visit_requests (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  visit_id UUID REFERENCES visits(id) ON DELETE CASCADE,
  imported_request_id UUID REFERENCES imported_requests(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(visit_id, imported_request_id)
);

CREATE INDEX idx_visit_requests_visit_id ON visit_requests(visit_id);
CREATE INDEX idx_visit_requests_imported_request_id ON visit_requests(imported_request_id);
```

### Логирование
Все действия записываются в `request_assignment_log`:
```sql
INSERT INTO request_assignment_log (imported_request_id, action, engineer_id, performed_by, reason)
VALUES ('<request_id>', 'assigned', '<engineer_id>', 'system', 'Автоматическая привязка октябрьских визитов (скрипт)');
```

## Ограничения

- ✅ Скрипт работает только с визитами октября 2026
- ✅ Скрипт не удаляет существующие привязки, только создаёт новые
- ✅ Если заявка уже привязана к другому визиту на том же адресе — привязка пропускается
- ✅ Скрипт идемпотентен — можно запускать повторно без риска дублирования

## Диагностика

### Проверка текущего состояния

```sql
-- 1. Визиты октября без привязок
SELECT 
  v.id,
  v.date_start,
  v.status,
  a.object_code,
  a.full_address
FROM visits v
JOIN addresses a ON a.id = v.address_id
LEFT JOIN visit_requests vr ON vr.visit_id = v.id
WHERE v.date_start >= '2026-10-01' 
  AND v.date_start < '2026-11-01'
  AND v.is_deleted = false
  AND vr.id IS NULL
ORDER BY v.date_start;

-- 2. Заявки октября, не привязанные ни к одному визиту
SELECT 
  ir.id,
  ir.external_request_id,
  ir.object_code,
  ir.start_date,
  ir.deadline,
  et.code AS equipment_type_code
FROM imported_requests ir
JOIN equipment_types et ON et.id = ir.equipment_type_id
LEFT JOIN visit_requests vr ON vr.imported_request_id = ir.id
WHERE ir.start_date >= '2026-10-01'
  AND ir.start_date < '2026-11-01'
  AND vr.id IS NULL
ORDER BY ir.start_date;

-- 3. Полная картина: визиты октября с привязками
SELECT 
  v.id AS visit_id,
  v.date_start,
  a.object_code,
  ir.external_request_id,
  ir.import_status
FROM visits v
JOIN addresses a ON a.id = v.address_id
LEFT JOIN visit_requests vr ON vr.visit_id = v.id
LEFT JOIN imported_requests ir ON ir.id = vr.imported_request_id
WHERE v.date_start >= '2026-10-01' 
  AND v.date_start < '2026-11-01'
  AND v.is_deleted = false
ORDER BY v.date_start, a.object_code;
```
