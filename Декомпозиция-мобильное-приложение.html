🎯 Подход: поэтапный ввод функционала

  • Каждый этап — самостоятельный релиз (APK для установки на телефон)
  • Одновременная работа PWA + mobile под одним пользователем невозможна — новый вход разлогинивает другие сессии
  • На ранних этапах — без офлайн-синхронизации (только online-режим, TanStack Query кэш)
  • Сначала просмотр, потом редактирование — убедимся, что данные приходят корректно
  • Тестирование на Xiaomi Redmi Note 10 Pro (393px, Android)

Этап 1 — Авторизация и профиль

Настройка проекта, вход, биометрия, PIN, профиль

15 задач~2-3 недели
Цель: APK, который можно установить на телефон. Инженер входит по логину/паролю, настраивает биометрию и PIN, видит свой профиль. Автоблокировка при неактивности. Визиты пока не загружаются.
IDЗадачаРазм.Зависимости
E1-01 Инициализация Expo проекта
npx create-expo-app (Expo SDK 52+, TypeScript). Expo Router (file-based routing). Структура: app/, src/, shared/ (symlink или копия shared/types). tsconfig, eslint, prettier. Тест: приложение запускается на Xiaomi через USB (Metro bundler).

PaperProvider + тема по палитре из спецификации (§5.0). Светлая/тёмная. useColorScheme для автопереключения. ThemeStore (Zustand) для ручного override.

axios instance с baseURL (production: домен сервера). Interceptor: добавляет Authorization header из Secure Store. Interceptor: при 401 → refresh token → retry. Обработка network errors. Тест: запрос к /api/auth/login с тестовым инженером.
Без offline-очереди — только online-режим

expo-secure-store: accessToken, refreshToken. Функции: getToken(), setTokens(), removeTokens(). Тест: после закрытия и reopening приложения — токен на месте.

useAutoLock hook: AppState listener. При background → таймер 5 мин. При возврате → если истёк → unlock.tsx (биометрия/PIN). Сессия не теряется — данные и открытый экран сохраняются.

Пакетная синхронизация: массив мутаций (до 50). Идемпотентность по client_mutation_id. Транзакционность. Тест: отправка 10 мутаций → все обработаны.

E4-04 SQLite: схема для офлайн

Запись в sync_queue при каждом действии. client_mutation_id (UUID). Статусы: pending → in_progress → completed/failed. Retry: до 5 раз, exponential backoff. Автосинхронизация при появлении сети (NetInfo listener).
