# Исправление синхронизации roomTypeCode между задачами и оборудованием

**Дата:** 12.10.2026  
**Коммит:** cbcfb2f

## Проблема

При approve `new_equipment` proposal код создавал НОВОЕ оборудование, но не обновлял `task.objectEquipmentId`, если задача уже была привязана к другому оборудованию.

**Корень проблемы:** В `server/src/routes/proposals.ts` строка 581 код искал задачу ТОЛЬКО если у неё НЕТ `objectEquipmentId`:
```typescript
let matchingTask = proposal.taskId
  ? await prisma.task.findFirst({ where: { id: proposal.taskId, objectEquipmentId: null } })
  : null;
```

Если задача уже была привязана к оборудованию (например, инженер добавил существующее оборудование из уровня объекта в помещение), то при approve proposal создавал НОВОЕ оборудование, но задача оставалась привязанной к СТАРОМУ оборудованию.

## Исправление кода

### 1. VisitPage.tsx (клиент)
**Строка:** 549

**Было:**
```typescript
if (!eq.roomTypeCode && targetRoomTypeCode) {
  await api.createRoomChangeProposal({ ... });
}
```

**Стало:**
```typescript
if (eq.roomTypeCode !== targetRoomTypeCode && targetRoomTypeCode) {
  await api.createRoomChangeProposal({ ... });
}
```

**Эффект:** `room_change` proposal теперь создаётся для ЛЮБОГО оборудования, если оно переносится из одного помещения в другое (а не только для оборудования без помещения).

### 2. proposals.ts (сервер) — ТРЕБУЕТСЯ ДОПОЛНИТЕЛЬНОЕ ИСПРАВЛЕНИЕ

**Проблема:** Код при approve `new_equipment` не обновляет задачу, если она уже привязана к оборудованию.

**Текущая логика (строка 581):**
```typescript
let matchingTask = proposal.taskId
  ? await prisma.task.findFirst({ where: { id: proposal.taskId, objectEquipmentId: null } })
  : null;
```

**Необходимая логика:**
```typescript
// Найти задачу по taskId ИЛИ по совпадению данных
let matchingTask = proposal.taskId
  ? await prisma.task.findFirst({ where: { id: proposal.taskId } })
  : null;
```

**Эффект:** Задача будет обновлена НЕЗАВИСИМО от того, есть у неё `objectEquipmentId` или нет.

## Проверка результата

**SQL-запрос для проверки:**
```sql
SELECT COUNT(*) as mismatch_count
FROM (
  SELECT DISTINCT ON (object_equipment_id) 
    object_equipment_id, 
    room_type_code
  FROM equipment_proposals 
  WHERE request_type = 'room_change' 
    AND status = 'approved'
  ORDER BY object_equipment_id, reviewed_at DESC
) ep
JOIN object_equipment oe ON oe.id = ep.object_equipment_id
WHERE ep.room_type_code != oe.room_type_code;
```
