# Скрипт связывания октябрьских визитов с заявками

## Проблема

Визиты, созданные в октябре вручную (без автопривязки), не связаны с заявками октября через таблицу `VisitRequest`.

Это означает:
- Инженеры не видят заявки в отчётах ТМ
- ТМ не может отследить выполнение заявок
- Отчёты по договорам показывают неполные данные

## Решение

Скрипт `link-october-visits-to-requests.ts` автоматически:
1. Находит все визиты октября (01.10.2026 - 31.10.2026), не имеющие привязок к заявкам
2. Для каждого визита ищет подходящие заявки по адресу и периоду действия
3. Создаёт связи в таблице `visit_requests`
4. Обновляет `imported_requests.visit_id`
5. Синхронизирует `contract_id` из заявки в визит
6. Логирует все действия в `request_assignment_log`

## Логика привязки

### 1. Заявки ИСЖ объекта (одна заявка → много визитов)
- Фильтр: адрес визита = адрес заявки, период визита в периоде заявки
- Одна заявка ИСЖ объекта может быть привязана к нескольким визитам (разные инженеры)
- Защита от дубликатов по периоду

### 2. Заявки на конкретное оборудование (1 заявка → 1 визит)
- Фильтр: адрес визита = адрес заявки, тип оборудования визита = тип заявки, период
- Заявка привязывается только если ещё не привязана к другому визиту
- Проверяется, что инженер добавил соответствующий тип оборудования в задачи визита

## Запуск на production

### Шаг 1: Диагностика (опционально)

Проверить, сколько визитов октября без привязок:

```bash
# Подключиться к БД
docker compose -f docker-compose.prod.yml exec -T db psql -U checklist -d checklist

# Выполнить SQL из файла scripts/link-october-visits.sql
\i scripts/link-october-visits.sql

# Или скопировать SQL вручную
```

### Шаг 2: Запуск скрипта связывания

```bash
# Из корня проекта
docker compose -f docker-compose.prod.yml exec -T server npx tsx scripts/link-october-visits-to-requests.ts
```

Скрипт выведет:
- Список обработанных визитов
- Количество привязанных заявок
- Детали по каждому визиту (адрес, дата, привязанные заявки)

### Шаг 3: Проверка результата

```bash
# Снова подключиться к БД
docker compose -f docker-compose.prod.yml exec -T db psql -U checklist -d checklist

# Проверить, что все визиты октября имеют привязки
SELECT 
  v.id,
  v.date_start,
  a.object_code,
  COUNT(vr.id) AS requests_count
FROM visits v
JOIN addresses a ON a.id = v.address_id
LEFT JOIN visit_requests vr ON vr.visit_id = v.id
WHERE v.date_start >= '2026-10-01' 
  AND v.date_start < '2026-11-01'
  AND v.is_deleted = false
GROUP BY v.id, v.date_start, a.object_code
ORDER BY v.date_start;
```

## Улучшения в коде

Помимо скрипта, улучшена логика автопривязки в `server/src/routes/visits.ts`:

1. **При создании визита** (`POST /api/visits`):
   - Автопривязка заявок ИСЖ объекта по адресу и периоду
   - Назначение инженера на заявку
   - Логирование в `request_assignment_log`

2. **При завершении визита** (`POST /api/visits/:id/complete`):
   - Автопривязка заявок ИСЖ объекта
   - Автопривязка заявок на конкретное оборудование (по типам задач визита)
   - Синхронизация `contract_id`

## Технические детали

### Таблица `visit_requests`
```sql
CREATE TABLE visit_requests (
  id UUID PRIMARY KEY,
  visit_id UUID REFERENCES visits(id),
  imported_request_id UUID REFERENCES imported_requests(id),
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(visit_id, imported_request_id)
);
```

### Индексы
- `visit_requests(visit_id)` — быстрый поиск связей визита
- `visit_requests(imported_request_id)` — быстрый поиск связей заявки

## Бизнес-правила

### ИСЖ объект
Заявка на ТО ИСЖ объекта означает обслуживание ВСЕГО оборудования объекта (ВИК, ИСЖ, ДГУ, ИБП). Каждый инженер создаёт свой визит в рамках своей специализации, все визиты привязываются к ОДНОЙ заявке.

### Конкретное оборудование
Заявка на конкретное оборудование (например, `splitvn` — внутренний блок сплит-системы) привязывается к одному визиту, который содержит задачу с соответствующим типом оборудования.

## Ограничения

- Скрипт работает только с визитами октября 2026
- Скрипт не удаляет существующие привязки, только создаёт новые
- Если заявка уже привязана к другому визиту на том же адресе — привязка пропускается
