# Реализация нового отчёта по заявкам

**Дата:** 07.10.2026  
**Статус:** ✅ Завершено (код написан, компиляция проходит)

## Что реализовано

### 1. Новый генератор HTML для отчёта по заявкам
**Файл:** `server/src/services/requestsReport.ts`

**Функции:**
- `generateRequestsReportHtml()` — генерация HTML для PDF
- `renderTask()` — рендеринг задачи с параметрами, фото, рекомендациями
- `renderPhotosGrid()` — рендеринг фотофиксации с проверкой дубликатов
- `renderParams()` — рендеринг параметров задачи (незаполненные → красным)
- `conclusionBadge()` — бейдж заключения с цветом

**Особенности:**
- Группировка по заявкам (не по адресам, как в старом отчёте)
- 8 KPI показателей (вместо 4 в старом)
- Расчёт SLA (выполнение в срок)
- Проверка дубликатов фото через `VisitAnomaly`
- Сортировка заявок: завершённые → в работе → не начатые

### 2. Новый endpoint для генерации отчёта
**Файл:** `server/src/routes/reports.ts`

**Endpoint:** `POST /api/reports/requests-generate`

**Параметры:**
```json
{
  "contractId": "string",
  "dateFrom": "YYYY-MM-DD",
  "dateTo": "YYYY-MM-DD",
  "periodType": "created" | "closed"
}
```

**Логика:**
1. Загружает все заявки договора
2. Фильтрует по периоду (дата создания или закрытия)
3. Для каждой заявки определяет статус (через `computeRequestStatus`)
4. Фильтрует визиты по статусам (completed, sent, corrected_by_tm, in_progress)
5. Подсчитывает KPI (визиты, задачи, объекты, SLA)
6. Проверяет дубликаты фото через `VisitAnomaly`
7. Генерирует HTML → PDF
8. Отправляет файл пользователю

### 3. Клиентский API метод
**Файл:** `client/src/api/client.ts`

**Метод:** `generateRequestsReport()`

**Использование:**
```typescript
await api.generateRequestsReport({
  contractId: "uuid",
  dateFrom: "2026-10-01",
  dateTo: "2026-10-31",
  periodType: "created"
});
```

### 4. Обновление UI
**Файл:** `client/src/pages/SummaryReportPage.tsx`

**Изменения:**
- Для режима `reportType='requests'` и `requestMode='contract'` используется новый метод
- Остальные режимы (period, objects, requests+numbers) используют старый `generateUnifiedReport`

## Структура отчёта (PDF)

### Лист 1: Титульный
- Название: "ОТЧЁТ ПО ЗАЯВКАМ"
- Период (дата создания или закрытия)
- Дата формирования
- ФИО сформировавшего

### Лист 2: Сводные KPI
8 карточек с показателями:
1. Общее количество заявок
2. Завершены
3. В работе
4. Не начаты
5. SLA (%)
6. Совершённых визитов
7. Выполненных задач
8. Обслуженных объектов

### Лист 3.n: Детализация по заявкам
Для каждой заявки:
- Заголовок: "Заявка: [номер] ([адрес])"
- Для каждого визита:
  - Дата, инженер, статус (цвет), задач, замечаний
  - Задачи с оборудованием, параметрами, фото, рекомендациями

## KPI и формулы

### SLA (выполнение в срок)
```
SLA = (Заявки, закрытые в срок / Общее количество закрытых) × 100%
```

**Логика:** Для каждой завершённой заявки проверяется, что дата последнего визита ≤ deadline заявки.

### Количество совершённых визитов
Сумма визитов по всем заявкам со статусами:
- `completed` (Завершён)
- `sent` (Отправлен)
- `corrected_by_tm` (Откорректирован ТМ)
- `in_progress` (В работе)

### Количество выполненных задач
Сумма задач с `conclusion` (ok, ok_with_notes, faulty) во всех визитах из предыдущего пункта.

### Количество обслуженных объектов
Количество уникальных адресов (`matchedAddressId`) из визитов.

## Проверка дубликатов фото

**Источник данных:** таблица `VisitAnomaly` (type='duplicate')

**Логика:**
1. Загружаются все аномалии type='duplicate' для фото в визитах договора
2. Создаётся Set с ID дубликатов
3. При рендеринге фото проверяется: `isDuplicate = duplicatePhotoIds.has(photo.id)`
4. Если дубликат — красная рамка и подпись "Дубликат"

## Отличия от старого отчёта

| Характеристика | Старый (`unifiedReport.ts`) | Новый (`requestsReport.ts`) |
|---|---|---|
| Группировка | По адресам | По заявкам |
| KPI | 4 показателя | 8 показателей |
| SLA | Нет | Есть |
| Проверка дубликатов | Нет (только phashWarning) | Да (через VisitAnomaly) |
| Сортировка | Нет | По статусу заявки |
| Структура листов | Адрес → Визиты | Заявка → Визиты → Задачи |

## Известные ограничения

1. **periodType='closed'** — пока не тестируется, так как у заявок может не быть deadline
2. **Режим 'numbers'** — использует старый отчёт (unifiedReport.ts), так как работает с конкретными заявками, а не с договором
3. **Удаление PDF** — файл удаляется через 60 секунд после отправки (может быть проблемой при медленном интернете)
