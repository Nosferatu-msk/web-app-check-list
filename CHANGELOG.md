# Changelog

## [2026-08-18]

### Улучшения UI/UX
- **Переработан раздел «Мои заявки» для инженера ТО** — полностью обновлён интерфейс страницы `/my-requests`:
  - **Мобильный вид**: карточки (`.request-card`) вместо таблицы с горизонтальным скроллом — компактное отображение с адресом, видом оборудования, статусом и кнопками действий
  - **Табы-фильтры**: переключатель «Все / Новые / В работе / Завершённые» (`Segmented`) для быстрой навигации по заявкам
  - **Умная логика кнопок**:
    - Для новых заявок (`planned`, `awaiting_assignment`, `not_started`) — кнопки «Начать визит» + «Отказаться»
    - Для заявок в работе (`in_progress`) — кнопка «Продолжить визит»
    - Для завершённых (`completed`, `sent`, ...) — без кнопок, карточка кликабельна
  - **Десктоп**: таблица без `fixed: 'right'` и `scroll.x`, `maxWidth: 1400px` — единый стандарт ширины
  - **CSS**: добавлены стили `.request-card` по аналогии с `.visit-card`

### Исправления
- **Автоматическая смена статуса визита на «В работе»** — визит автоматически переходит в `in_progress` при:
  - Создании или обновлении задачи (серверный эндпоинт `PUT /:visitId/tasks/:id` и `POST /:visitId/tasks`)
  - Первом посещении страницы визита инженером (клиентский `VisitPage.tsx`)
  - Это решает проблему, когда заявка отображалась как «новая» после начала работы инженера
- **Исправлены существующие данные** — 121 визит с задачами обновлён со статусов `not_started`/`planned` на `in_progress`

## [2026-08-17]

### Новые функции
- **Автоназначение инженера на заявки при создании визита** — при выборе адреса инженером (ВИК/ИСЖ) система проверяет наличие неназначенных заявок по этому адресу. Если найдены — предлагается назначить инженера автоматически. Назначение происходит через `VisitEngineer`, запись в `RequestAssignmentLog` с причиной "Автоматически при создании визита"

### Исправления
- **Доступ к визиту для вторичных инженеров** — `canAccessVisit` не учитывал таблицу `visitEngineers`, из-за чего вторичный инженер получал 403 при переходе по кнопке «Начать визит». Теперь проверяется наличие записи в `visitEngineers`
- **Бесконечный спиннер при загрузке визита** — `api.getVisit(id)` вызывался без `.catch()`, при ошибке (403/404/сетевая) `loading` оставался `true`. Добавлена обработка ошибок с сообщением и возвратом на страницу заявок
- **Список визитов не включал визиты из visitEngineers** — инженер видел только визиты, где он основной (`userId`). Теперь фильтр включает визиты, где инженер назначен через `visitEngineers`
- **Отображение инженеров в списке визитов** — показывались только основной инженер. Теперь отображаются все назначенные инженеры (основной + вторичные через `visitEngineers`)
- **Кнопка «Назад» отсутствовала в «Мои заявки» на десктопе** — добавлена кнопка возврата к списку визитов

### Улучшения
- **Подстановка ФИО текущего инженера** — при открытии визита инженером в поле «Инженер» автоматически подставляется ФИО текущего пользователя (а не сохранённое значение)
- **API возвращает visitEngineers** — эндпоинты `GET /api/visits` и `GET /api/visits/:id` теперь включают данные о всех назначенных инженерах

### Данные
- **Исправлены привязки объектов CA/77/*** — 504 объекта с кодом CA/77/* были привязаны к ТМ_МБ вместо test_tm_ca@test.ru. Привязки перенесены на корректный ТМ

## [2026-08-04]

### Исправления
- **Статус задач не менялся при сохранении** — виртуальные задачи климата (группировка splitvn по помещениям) не имели поля `status`, поэтому всегда отображались как «Не начато» независимо от статусов реальных задач. Добавлено вычисление статуса виртуальной задачи на основе статусов реальных задач (`completed` / `in_progress` / `not_started`)
- **Автосохранение не обновляло статус задачи** — `handleAutoSave` и `handleGoToPhotos` в TaskPage и GroupTaskPage не отправляли `status` при сохранении. Теперь при любом сохранении (явном, автоматическом, при переходе к фото) статус меняется на `in_progress`, если задача ещё не `completed`
- **ТМ ТО перенаправлялся на «Заявки» вместо «Визиты инженеров»** — `SmartRedirect` для роли `tm` перенаправлял на `/requests` вместо страницы визитов. Теперь ТМ перенаправляется на `VisitListPage` с заголовком «Визиты инженеров»
- **ТМ ТО не мог зайти в визиты своих инженеров** — `EngineerRoute` не пропускал роль `tm`, поэтому при клике на визит ТМ возвращался на список. Добавлена роль `tm` в проверку `EngineerRoute`

### Модуль МТР — Исправления
- **Админ получал 403 при GET /api/mtr/visits** — добавлен middleware `engineerMtrOrAdmin`
- **Кнопка удаления визита отсутствовала для статусов completed/sent/rejected** — теперь доступна для всех статусов
- **ФИО инженера не отображалось в карточке визита МТР** — добавлен `engineer` в `include` для роутов
- **GET /admin/users не фильтровал по параметру role** — из-за чего привязка ТМ МТР к инженеру возвращала 400

### Модуль МТР — Новые функции
- **Форма создания визита МТР приведена к виду ТО** — Ant Design Form, DatePicker, TimePicker, Select с поиском
- **Поле «Инженер» в форме создания** — disabled, автозаполнение ФИО
- **Секция просмотра визита приведена к стилю Ant Design**
- **Экран завершения визита** — с предложением сформировать отчёт или вернуться к визитам
- **Статус при завершении меняется на completed** (как в ТО), без модального окна подтверждения
- **Генерация отчёта МТР** — PDF через Puppeteer + ZIP-архив с фото (аналогично ТО)
- **Редактирование завершённых визитов** — при сохранении completed визита статус меняется на `in_progress`, если условия завершения не выполнены
- **Повторная генерация отчёта** для завершённых визитов

## [2026-08-03]

### Новые функции
- **Управление специализацией видов оборудования** — администратор может назначать и изменять требуемую специализацию (ВиК, ИСЖ, ГПМ, ДГУ, ИБП) для каждого вида оборудования через админку. Добавлена колонка «Специализация» в таблицу видов оборудования (цветные теги) и поле Select в форме создания/редактирования. Пустое значение = доступно всем специализациям
- **Импорт специализации через CSV** — при импорте видов оборудования поддерживается колонка `specialization_req` (vik/iszh/gpm/dgu/ibp). Некорректные значения валидируются с ошибкой по строке

### Исправления
- **Фильтрация оборудования по специализации в модальном окне добавления** — эндпоинты `other-rooms` и `rooms` теперь фильтруют оборудование по специализации инженера. Ранее инженер видел оборудование из других помещений и список помещений без учёта своей специализации (например, инженер ВиК видел ИБП, кулеры и т.д.)
- **Пагинация на странице «Заявки»** — исправлен переход на вторую и последующие страницы. Обработчик `onChange` таблицы Ant Design вызывался и при смене страницы, и при сортировке, и всегда сбрасывал `page=1`. Теперь корректно различаются: смена страницы → сохранение номера, смена pageSize → сброс на 1, сортировка → сброс на 1.
